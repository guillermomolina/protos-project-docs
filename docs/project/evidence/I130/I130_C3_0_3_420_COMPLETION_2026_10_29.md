The IDNA reference and certificate DNS-ID parser now accepts only valid ASCII NR-LDH labels or canonical IDNA2008 A-labels. Punycode (RFC 3492) must decode to Unicode scalar values, survive canonical round-trip and meet RFC 5890–5893 derived-property, CONTEXTJ/CONTEXTO, Bidi and normalization rules. Original non-ASCII U-label input is **not** converted or admitted. This policy is owned by Protos `Identity.protos`; the narrow private Java facility supplies ICU Unicode property/normalization facts and the Native Image metadata registers required `nfkc.nrm`. Both caller references and presented SAN DNS-IDs are validated; malformed SANs are skipped. RFC 9525 SAN-only matching, the one-leftmost-label wildcard, exact numeric-IP SAN matching, no Common Name fallback and DNS-only lowercase ASCII SNI remain intact. The two test leaves separate valid A-label identity from malformed SANs; the five checked-in PEM fixtures do not include the issuing CA private key.

The `native-tls-tests` Maven profile now selects exactly `ProtosTlsClientIntegrationTest` and `ProtosTlsTrustTest` itself (not just via the Makefile's `-Dtest` safeguard) and deletes stale Surefire test IDs before discovery. The interpreter-only fallback warning is suppressed **only as a runtime argument to this Native TLS test executable**, not in the JVM tests, normal launcher or production Native Image. The separate JVM optimizing-runtime/fallback contract and the existing `build/native/Makefile` filter remain protected by the architecture test.
