## Published product delta, verified against the exact commit

The human-published product commit has 22 changed paths:

- Normative: new `spec/io/TLS.md`; cross-reference additions `spec/io/HTTP.md` and `spec/io/NETWORK.md`; standard `TlsError` taxonomy in `spec/semantics/ERRORS.md`; canonical specification navigation `AGENTS.md`; revision `spec/PROTOS_SPEC_CHANGELOG.md`.
- Private Java host primitives, package `com.guillermomolina.protos.execution` under `src/main/java/com/guillermomolina/protos/execution/host/tls/`: `ProtosTlsClientEngine`, `ProtosTlsTrust`, `ProtosTlsTrustVerifier`, and `ProtosTlsFailure`. No public TLS module or server/backend registry was published in A.
- Java/JVM unit tests in `src/test/java/com/guillermomolina/protos/execution/host/tls/`: `ProtosTlsClientEngineTest`, `ProtosTlsTrustTest`, `ProtosTlsTestPeer`.
- Seven test-only certificate/key PEM fixtures under `src/test/resources/tls/`.
- Finalization metadata: `pom.xml` and `CHANGELOG.md` with version `0.3.413-SNAPSHOT`.

The private `SSLEngine` adapter has transport-neutral wrap/unwrap/delegated-task and bounded-buffer methods; it configures an allowed secure protocol/suite profile before negotiation and defensively reads the negotiated result. Separate PKIX trust-manager checks and exact DER/SAN material decoding return backend facts without claiming Protos identity/error semantics. The engine does not perform socket I/O. The public frontend, policy, Trust descriptors, cancellation/queue/duplex behavior and HTTP composition remain **I130-B**, with hardening/Native Image feasibility in **I130-C**.

**Protos-first ownership:** The implementation evidence in A is a foundation, not an endorsement of moving portable policy to Java. `protos/lib/tls/Client.protos` and the planned `protos/lib/tls/internal/` modules are not in this commit. The approved S12 frontend remains the authority.
