## Normative reconciliation actually published

The exact published `spec/io/TLS.md` and global specification entry **0.1.478** include:

1. **Trust:** missing, unreadable, empty or unusable selected Java `cacerts` maps to `TlsError.kind = "trustUnavailable"` before TLS traffic, without fallback/union; usable selected anchors failing peer verification map to `untrustedPeer`. This is the explicit already-approved error-kind clarification left incomplete by I130-A.
2. **Identity:** reference DNS names temporarily accept ASCII NR-LDH labels only. Every reserved R-LDH label (`--` at positions 3–4), including valid and invalid `xn--` A-labels, is rejected; a certificate DNS-ID containing such a label cannot establish identity. No implicit U-label conversion, permissive fallback or public-suffix infrastructure.
3. **Handshake cleanup:** when an owning handshake fails with an ordinary Error, that original Error wins over a later owned transport close Error. If cancellation is the prior transfer and cleanup fails, the cleanup Error wins. This TLS-specific arbitration leaves Core `ensure` unchanged.
4. **Secure-duplex close:** `IO_CORE.md` §9 wrapper-close ordering and failure precedence apply; a failing close_notify emission wins over a later owned lower close failure.
5. **Deferred classification:** §13 explicitly identifies full IDNA2008 A-label support as **incomplete conformance** to approved D220–S12, not a new or deferred architecture decision.

The normative document is authoritative; this record does not approve, override or retroactively redefine D220–S12. The temporary A-label exclusion is a published implementation limitation, so **D220 remains open** for full invariant reconciliation.
