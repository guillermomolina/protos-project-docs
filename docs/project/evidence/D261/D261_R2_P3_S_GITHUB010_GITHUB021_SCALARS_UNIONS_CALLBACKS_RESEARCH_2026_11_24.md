## 1. Exact question and bounded design space

Choose the proportional R2 **public C ABI scalar and aggregate contract**, and explicitly decide whether the initial R2 subset includes native C callbacks. P3-S contains four independently testable axes:

- **S-scalar:** fixed-width signed/unsigned scalars, native ABI canonical types, binary32 rounding, Boolean/char/enum/long-double admission and lossless value conversion.
- **S-aggregate:** struct/union/array layout, alignment/padding, native overlap, active member for value snapshots, by-value function ABI, packed and bit-field limits.
- **S-object:** field names colliding with ordinary Protos methods like `call`, `createSlot`, `slotValue`, `init`; ordinary source-side `readAs/writeFrom` must not gain magic property semantics or an undocumented privileged reflection primitive.
- **S-callback:** C-to-Protos same-dynamic-extent upcalls vs retained callbacks, foreign-thread ingress, Task/Actor reentrancy, error/nonlocal return propagation, Native Image metadata and the cost of deferring the API.

**Do not conflate:** (i) native C bit-level layout, (ii) an ordinary Protos snapshot of selected values, (iii) Java FFM carrier representation, (iv) the Core value taxonomy, or (v) an independently authorized downcall/upcall. A C library's ABI declaration is trusted; Java FFM cannot validate that library's machine-level signature.

## 3. Prior-art survey — more than five systems, at least three approaches

**Route A — explicit C ABI layouts and bounded Java/Truffle substrate**

1. **OpenJDK 25 FFM**: [MemoryLayout](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/foreign/MemoryLayout.html) `structLayout`, `unionLayout`, `sequenceLayout`, `paddingLayout`, `byteOffset`, `varHandle`. **`structLayout` does not insert C padding automatically**. `unionLayout` overlays members. [Linker](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/foreign/Linker.html) `canonicalLayouts` is platform dependent: C `long` maps differently on Linux x64 vs Windows x64 and unsigned types ordinarily use the same carrier layout as corresponding signed. By-value group return requires [SegmentAllocator](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/foreign/SegmentAllocator.html). [`upcallStub`](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/foreign/Linker.html) **can abruptly terminate the JVM if its method-handle target throws an exception**; a containment trampoline is not optional for faithful Protos Errors.
2. **GraalVM 25 Native Image**: [FFM guide](https://www.graalvm.org/jdk25/reference-manual/native-image/native-code-interoperability/ffm-api/), explicitly supports structured C by-value calls and upcalls but requires exact build-time downcall/upcall descriptors. Direct-target upcall registrations give materially better codegen than generic stubs. *Runtime JVM success does not imply Native Image exact ABI descriptor availability.*
3. **TruffleRuby**: pinned [`FFMSupport.carrierLayout/functionDescriptor/createDowncallHandle/createUpcallStub`](https://github.com/truffleruby/truffleruby/blob/1ed85bd26ca507e0c3330426e94727bf6b4c5c0c/src/main/java/org/truffleruby/platform/FFMSupport.java) and [`PointerNodes` `@Specialization`](https://github.com/truffleruby/truffleruby/blob/1ed85bd26ca507e0c3330426e94727bf6b4c5c0c/src/main/java/org/truffleruby/extra/ffi/PointerNodes.java), [`struct_layout.rb`](https://github.com/truffleruby/truffleruby/blob/1ed85bd26ca507e0c3330426e94727bf6b4c5c0c/lib/truffle/truffle/ffi_backend/struct_layout.rb). Supports B/S/I/L/F/D carrier families and explicit field offsets/read/write. Native upcall lifetime and code generation demand care; TruffleRuby's raw integer pointer design is **not** an acceptable justification for numeric native address forging in Protos.
4. **GraalPy**: pinned [`CStructAccess.allocate/readShortField/readIntField/writeIntField/readDoubleField`](https://github.com/oracle/graalpython/blob/12a66f9ef7ed7fd26f013d72ab8bec0a1da6ad6b/graalpython/com.oracle.graal.python/src/com/oracle/graal/python/builtins/objects/cext/structs/CStructAccess.java), [`NativeMemory`](https://github.com/oracle/graalpython/blob/12a66f9ef7ed7fd26f013d72ab8bec0a1da6ad6b/graalpython/com.oracle.graal.python/src/com/oracle/graal/python/runtime/nativeaccess/NativeMemory.java), [`GenerateNativeDowncallsProcessor.collectDowncalls/generateInvoker`](https://github.com/oracle/graalpython/blob/12a66f9ef7ed7fd26f013d72ab8bec0a1da6ad6b/graalpython/com.oracle.graal.python.processor/src/com/oracle/graal/python/processor/GenerateNativeDowncallsProcessor.java). Specialized native scalar/field operations and build-oriented downcall descriptors have direct Truffle precedent; GraalPy's CPython ABI compatibility is a different scope from Protos's guest numerical semantics.

**Route B — broad dynamic ctypes/FFI projection**

5. **CPython ctypes**: [official docs](https://docs.python.org/3/library/ctypes.html) show `c_float`, fixed-width types, Structure/Union `_fields_`, bit-fields/pack options, and callback `CFUNCTYPE`. The docs **explicitly disclaim by-value unions and bitfield structs** as generally supported, recommend pointer passage, and warn that C-held callbacks without retained Python references can crash the process. Callbacks from foreign-created threads create dummy Python threads, behavior **forbidden by Protos ACTORS §24J**. Python's implicit field descriptors and dynamic classes should not be transplanted into Protos.
6. **LuaJIT FFI**: [FFI semantics](https://luajit.org/ext_ffi_semantics.html) and [FFI API](https://luajit.org/ext_ffi_api.html): C declarations, arithmetic/narrowing and native union field overlays through a dynamic cdata model. Attractive concision but its raw casts/address access and C cdata model differ from Protos's ordinary prototype/typed-region split and M3 custody.
7. **Ruby FFI / struct metadata**: TruffleRuby `struct_layout.rb` maps field names/offsets/types, supporting an implementation-independent library facade; explicit inline-array special cases show how easily convenience wrappers accrue hidden complexity. Do not treat built-in Ruby property readers as an approved Protos Core feature.

**Route C — native-layout declarations and explicit variants/safety**

8. **Rust `#[repr(C)]` union and FFI**: [Rust Reference unions](https://doc.rust-lang.org/reference/items/unions.html), [layout rules](https://doc.rust-lang.org/reference/type-layout.html). C union storage has **no runtime notion of active field**; reading a different interpretation requires user discipline/unsafe code. Tagged unions require explicit tag check before selecting arm. Rust `repr(C)` layout padding/alignment rules guide ABI fixture design, not Protos ownership syntax.
9. **Zig `extern struct`/`extern union`**: [Zig reference](https://ziglang.org/documentation/master/); explicit ABI layout and access to untagged union without automatic tag invention. Its `packed` and bitfield facilities are separate policies; another reason not to infer them from ordinary `FFI.struct` members.
10. **.NET P/Invoke**: [Customizing structure marshalling](https://learn.microsoft.com/dotnet/standard/native-interop/customize-struct-marshalling), [LayoutKind.Explicit](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.interopservices.layoutkind). Supports explicit field overlays with `FieldOffset(0)` and distinct native value/pointer marshaling, but uses managed class/struct attributes absent from Protos's object model. Its direct callback/delegate model has runtime rooting obligations, not a free closure adapter.

**Additional Truffle breadth:** Espresso has JVM/JNI-native integration rather than Protos-specific C struct value semantics; Sulong/LLVM runs guest LLVM/C pointer semantics in an IR runtime rather than wrapping Java FFM for source Protos; GraalJS has JS-specific Java/Node interop without a generally equivalent public ABI layout module; SimpleLanguage is a teaching guest without mature C aggregate/upcall ABI; Apple Pkl is a configuration language and lacks a materially comparable native C FFM surface. These systems do **not** supply a more relevant R2 scalar/union/callback contract than the surveyed implementations. No plan copies their language-level object or callback models.

### Non-compensating red flags and strongest objections

- **S0 underengineering:** choosing it after G2/P2/C1/M3 would leave the project unable to bind R2 group types and require per-library shims.
- **S1 underengineering:** refusing union field views and binary32 entry hampers common C APIs. Expansion later is possible, but must not silently change a strict f32 declaration's semantics.
- **S3 disqualified:** hidden `.field` native mutation violates P2 and Object Model; automatic guessed active union member has no basis in untagged C; retained/foreign-thread callbacks contradict ACTORS §24J and G2; unsafe numeric pointers violate M3. High capability or ergonomics cannot compensate.
- **S4 strongest credible alternative:** no lossy f32 admission at bind, strictly preserves R1 no-rounding; callers can use an explicit `FFI.roundF32` first. Cost: nontrivial source friction for C `float` APIs; the conversion remains necessary and gets moved to extra calls/metadata.
- **S5 strongest capability objection against S2:** real C libraries use `qsort`, `sqlite3_exec`, comparators, event callbacks. A synchronous native upcall is technically available and the Core contract already exists. Deferral may temporarily require C adapters. Against immediate implementation, **OpenJDK 25 says an exception escaping an `upcallStub` target may terminate the JVM**; faithfully preserving Protos Error identity/non-local-return behavior through a C ABI boundary requires an explicit outcome-capture/reentry contract and independent JVM/Native Image tests. P2/C1/M3 are not an authorization to invent that machinery.

## 6. S2 recommendation — exact conceptual contract, owner gate OPEN

### 6.1 ABI scalar universe (separate from Core Number)

Retain R1 `FFI.void/i32/i64/f64/sizeT/utf8z` and extend in the proposed R2 profile with **`FFI.i8/u8/i16/u16/u32/u64/f32`**. Fixed-width signed `iN` accepts exact Protos Integer in `[-2^(N-1), 2^(N-1)-1]`; unsigned `uN` in `[0, 2^N-1]`. Out-of-range, wrong numeric family, Fraction, Complex and implicit Integer-to-Float coercion fail *before* native entry. All integral native returns become exact Protos Integer (including `u64=18446744073709551615`, a BigInteger). No `Int`/`UInt`/f32 Core prototype/value category.

**F32 is an explicit, new typed ABI narrowing contract:** choosing `FFI.f32` in the signature is deliberate permission to convert input Protos binary64 Float to IEEE binary32 **round-to-nearest, ties-to-even**, then pass the actual native float. Native float return is widened exactly to a Protos binary64 Float; preserve signed zero, infinities and NaN *semantic* equivalence (not NaN bit payload). Tests must cover subnormal, overflow to infinity, underflow to signed zero and ties. **This explicitly changes the R1 no-rounding law for the new `f32` descriptor alone; it does NOT permit rounding `iN` or `f64`, numeric coercion or silent wrap.** Owner must approve this disclosed exception; if rejected, select S4 instead.

**Native C type names are not numeric families:** proposed `FFI.cType(name)` only recognizes exact keys/ABI canonical layouts actually supported by `Linker.canonicalLayouts()` *and* a well-defined guest conversion policy. C `long`, `unsigned long`, `size_t`, `ptrdiff_t`, `char`, `_Bool` and native enums must not blindly be guessed from Java widths: canonical Java layouts for signed/unsigned often coincide, and C `char` signedness and enum width may require the C ABI declaration or independent C fixture. For booleans, only a separately verified native `_Bool` descriptor may convert canonical Protos Booleans to/from valid C `_Bool` values. `long double`, `__int128`, compiler vector types and unknown enums are rejected unless a later independently verified layout/return-carrier contract is approved. No automatic reinterpretation of `sizeT` or `cType` across platform profiles.

### 6.2 Structs, unions, arrays and ABI by-value

Layout composition is by immutable descriptors. On supported Linux x86-64 LP64, verify exact sizes, field offsets, alignment, internal/tail padding and array stride against native C `sizeof`, `_Alignof`, `offsetof`. **JDK `MemoryLayout.structLayout` does not auto-pad:** a source-level friendly layout builder must insert correct padding or reject unsupported declarations; low-level `FFI.padding(bytes)` remains an independently proposed explicit option. `unionLayout` expresses overlapping storage; a C union without an external discriminant has **no universally discoverable active member**.

- **Live union region:** `region["member"]` explicitly selects the declared interpretation; reading an invalid bit pattern or pointer from an inactive field is a trusted native risk (M3), not an automatic union discriminator. Each pointer field returns a bounded/pass-only native capability according to M3 provenance, never inherits the union's whole storage as pointee extent.
- **Ordinary snapshot `FFI.readAs`/ `FFI.writeFrom`:** for layouts containing unions, require explicit **caller-supplied active-member selection for each union path**. Do not materialize *all* overlapping members as independent ordinary slots; doing so would fabricate data and violate by-value independence. Writing an active member updates the selected representation only and must not silently preserve or infer an unrelated inactive member. Named tagged unions in C require separately declared tag-based selection logic at the source library layer.
- **Nested struct/array:** stage and validate full relevant fields, bounds, layout and union selection before native writes to avoid observable partial writes from type/range failure; do not promise atomically coherent observation against native C threads. Check aggregate by-value ABI argument/return classification; Java group return requires a `SegmentAllocator` whose storage outlives the call-temporary arena. **No reinterpretation of a by-value aggregate as `ADDRESS`** to satisfy finite Native Image scalar shape sets.
- **Defer bitfields/packed/flexible-array/variadic:** bitfields have compiler-specific ordering/width and generally cannot be modeled by arbitrary ordinary member sizes; packed and flexible array layouts need dedicated tests/specific public contracts; `Linker.Option.firstVariadicArg` requires default C promotions and exact registration. A default `struct/union` must reject unsupported forms rather than silently assume they work. C++ class/virtual ABI remains excluded by G2.

### 6.3 Arbitrary C field names versus ordinary Object selectors

P3-C1/P2 prohibit hidden `.` native access. A C field named `call` or `createSlot` becomes an ordinary local slot on a Protos snapshot and may shadow an inherited method. This is **intended**, not an FFM bug; calling an object whose `call` slot holds a number fails under the ordinary invocation contract.

However, generic source-side snapshot construction has a real admission limitation: even with D262 `createSlot`, a prototype may **already** override `createSlot`; and after inserting a field named `slotValue`, an ordinary source-side `value.slotValue(name)` may no longer refer to canonical reflection. Do not invent privileged Java reflection bypass.

**Recommended bounded compatibility:** the first `readAs(prototype,region)` convenience adapter requires a prototype whose normal new child has accessible canonical `createSlot` before field insertion. It can bind the ordinary method **before** inserting any conflicting fields and keep it private for subsequent insertions; verify its ordinary extracted-Closure receiver binding. The first `writeFrom(region,value)` must either operate only on proven source objects carrying pre-collision canonical reflection closures, or reject arbitrary reflective collisions before any write. A separate field-association Map/Array input can provide fully general C field-name interoperability without altering Object behavior; final public spelling is an **explicit next API decision**, not ratified by S2. Native region `at/atPut` remains universally available for valid layout field names and does not depend on D262 or snapshot reflection.

### 6.4 Callback/upcall scope — explicit defer, no policy change

Do **not** expose an FFM native callback/upcall constructor in the initial R2 surface. This is a deliberate **absence**, not a different callback semantic. The existing generic synchronous foreign callback contract in `VALUES_AND_COLLECTIONS.md` / `ACTORS.md` is preserved for providers that expose it and must apply when an FFM callback facility is later justified.

Reasons: the C callback C ABI cannot propagate an arbitrary Protos Error or non-local return as an ordinary C return value; Java 25 `Linker.upcallStub` requires a target method handle that cannot leak an exception or the JVM may abruptly terminate. A correct future FFM adapter needs guarded callback outcome capture, exact same Task/Actor/segment identity, suitable C-return fallback and delivery of the original Protos failure when the enclosing C operation returns; needs rejection of C-created threads, strong lifetime during dynamic extent, no retained stubs, no callback Future/suspension, nested reentrant calls, Native Image exact direct-upcall metadata and genuine JVM/AOT fixture proof. These are not just one FFM type descriptor.

Future `qsort`, `sqlite3_exec`, GLib/GTK signal callbacks or terminal library callbacks are useful evidence for a separately selected bounded slice. No universal native-thread-to-Protos queue/broker is selected. Native libraries implementing compatible **non-callback C ABIs remain usable in R2**, and callback-dependent APIs are explicitly unsupported pending that future slice.

## 8. Incremental design: present cost, deferral and real future risk

**Smallest coherent capability today:** scalar signed/unsigned fixed widths, explicit f32 narrowing contract, composable C struct/union/array layouts, live native memory access, explicit union member selection for semantic snapshots, source-library collision admission, by-value structures on verified ABI; ordinary RootActor Closure downcalls. Build this in bounded slices, not one release-sized Java change.

**Costs paid only if used:** descriptor creation/validation, layout calculations and Native Image **registered** shapes (build-time), native region allocations and C call conversion. An unused `std:ffi` import remains inert and never acquires native code; no automatic upcall environment, thread, broker or callback roots.

**Plausible regret for S2:** C-based callbacks such as `qsort` and GLib signals are unavailable initially, and a caller needs an authorized native adapter for some C functions. Escape: add a deliberately bounded same-segment callback descriptor later, using already standard Core callback semantics; no change to S2 scalar/region identity or C1 model. Do not promise retained callback APIs without a new explicit decision.

**Cost of delaying f32 rounding selection:** if first R2 publishes an exact-only f32 descriptor, later silently making it round changes observable accepted inputs; so select exact or rounded now rather than guess in Java. Conversely deferring callback implementation is reversible because R1/R2 have not published an FFM callback promise. The strongest objection to S2 is the missing widely useful callback capability; the strongest objection to S4 is needless friction calling ordinary C `float` APIs.

**Platform and scale stress:** Windows LLP64 `long`, `wchar_t`, C `char` signedness, possible C enum widths, Darwin/AArch64 ABI and C aggregate return classification all require independent platform profile gates. C++ class/virtual/mangling ABI is excluded. Trusted C can mutate untagged union bytes or free pointers regardless of guest validation. Many Actors/Tasks/Processes do not share a mutable FFM session or native region; G2 restricts general native FFM to Process RootActor. Native Image compiled downcalls and data layouts can scale independently of callback support.

**Pay-as-you-grow versus future-preimplementation:** no per-field Java class, no spec-wide new numeric prototype, no universal C compiler/parser, no automatic foreign-thread attach, no global callback scheduler, no hidden C union discriminant or native `.name` getter. These would make present users pay for speculative generality.

## 10. Recommended owner decision and downstream gates

**Recommendation: select S2** as the proportional P3-S public-contract direction, with these *explicitly visible* subchoices:

- **S2-F:** fixed signed/unsigned 8/16/32/64 + existing scalar descriptors, **f32 round-to-nearest/ties-even** as a deliberate new descriptor-only exception to the old no-rounding input law, Float binary64 results; only verified canonical C type keys.
- **S2-U:** C ABI struct/union/array with correct native overlap/padding; **no guessed union active field**; explicit caller-selected member path for ordinary snapshots; by-value aggregate only after exact JVM and Native Image ABI fixture admission; bitfield/packed/flexible/variadic deferred.
- **S2-H:** fields named `call/init/createSlot/slotValue` remain ordinary Protos data slots. No magic native dot properties; source snapshot/ordinary-field-reading is subject to canonical reflection visibility, otherwise explicit Map/Array association fallback (exact public API later).
- **S2-C:** **defer native FFM upcalls/callbacks** in the first R2 implementation, preserving established synchronous foreign callback semantics and allowing a future independently approved same-segment-only API with guarded errors, no foreign-thread ingress, no retained callbacks.

**Approval gate:** An owner must approve S2 and specifically acknowledge f32 rounding versus R1, union snapshot selection and callback deferral. Only then create a durable selected-decision record. An approved *direction* still does not approve all `FFI.*` names, every canonical type name, error precedence, alternate snapshot map API, memory-anchor sub-API or native call registration implementation. The remaining P3 exact API gate must resolve those separately.
