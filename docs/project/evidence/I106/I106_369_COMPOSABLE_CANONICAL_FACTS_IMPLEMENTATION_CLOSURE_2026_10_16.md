An unrelated or mismatched body/scope query requires persistent authority or returns no call candidates; it never authorizes an optimization.

## Acceptance and non-claims

- **Reported human validation:** clean `git diff --check`; full local tests PASS. The owner explicitly confirmed both following publication. The discussion leading to validation identified focal suites `ProtosI106ComposableCompilationFactsTest`, `ProtosI096InlineClosureLiteralCallTest`, `ProtosI101ProfileSpecializedLoweringTest`, `ProtosPerf042IdentityBuilderOracleTest`, `ProtosI095BooleanControlInlineTest` and `ProtosI095BooleanProtocolInlineTest`; this record does not fabricate per-suite counts or exact command-output artifacts.
- **Semantic/physical boundary:** no approved source-language syntax/specification change, new ordinary-call ABI, alternative Truffle Bytecode DSL interpreter, new Closure runtime category or physical capture redesign. The B5 ABI and NORMAL/DEBUG emission constraints remain authoritative. Effective-body, non-suspension and physical layout facts remain post-emission concerns.
- **Root groups and contexts:** the implementation preserves separate whole-tree versus isolated analyses, Builder-local layout/materialization, retained Bytecode parser reparse and independent destination Context profile reconstruction. Source-analysis tests alone do not prove guest execution; existing executable I095/I096/I101/oracle regressions supply the complementary maintainer-reported acceptance.
- **Performance:** this is compiler proof-ownership/reuse work, **not** a measured speedup. No new Graal final-tier graph, warmup stability result, runtime benchmark or peer comparison is claimed. [PERF042/#871](https://github.com/guillermomolina/protos/issues/871) remains independently owned and is not closed by I106.
