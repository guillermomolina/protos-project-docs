## Development-container Java selection finding

The first rebuilt 25.4 devcontainer exposed a real development-environment
selection mismatch even though the static toolchain bindings were otherwise
aligned:

```text
JAVA_HOME=/opt/graalvm-community-java25i4
PATH=/home/vscode/.local/bin:/home/vscode/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
command -v java=/usr/bin/java
resolved bare java=/usr/lib/jvm/java-21-openjdk/bin/java
bare java.version=21.0.12.1
bare java.vendor=Red Hat, Inc.

mvn -version:
  Apache Maven 3.9.9 (Red Hat 3.9.9-3)
  Java version: 25.0.4.1.1
  vendor: GraalVM Community
  runtime: /opt/graalvm-community-java25i4
```

Thus Maven respected `JAVA_HOME`, while an interactive bare `java` still
selected the OL10 system JDK 21 installed by the Maven OS package. DIST006-A
corrected this by making `${JAVA_HOME}/bin` precede the inherited PATH in the
devcontainer and by adding the fail-closed `devcontainer.java_path` toolchain
binding plus verifier tests.

After rebuilding the corrected container:

```text

  (build 25.0.4.1.1+1-jvmci-25.4-b23)
OpenJDK 64-Bit Server VM GraalVM CE 25.4.4.1.1+1.1
  (build 25.0.4.1.1+1-jvmci-25.4-b23, mixed mode, sharing)
```

## Scope and remaining DIST006 work

DIST006-A establishes the canonical version/toolchain migration only. It does
not claim completion of the remaining owner obligations:

- DIST006-B: runtime/tool/debug compatibility, including explicit runtime,
  generated Bytecode DSL, source/instrumentation and DAP/debug validation;
- DIST006-C: portable distribution, Native Image/container closure, maintained
  docs/version/changelog reconciliation, and final integrated closure evidence;
- DIST006-D: post-adoption 25.4 performance baseline.

`build/native/Dockerfile` remains intentionally outside DIST006-A because the
native-image digest/version closure belongs to DIST006-C. Historical 25.3
records remain historical evidence and are not rewritten by this slice.

## Version/changelog finalization
