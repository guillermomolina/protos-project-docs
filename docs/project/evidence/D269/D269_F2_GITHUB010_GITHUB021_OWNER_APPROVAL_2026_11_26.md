## GITHUB010 comparison

Primary precedent families and links for re-verification:
- [Python time](https://docs.python.org/3/library/time.html) and [asyncio tasks](https://docs.python.org/3/library/asyncio-task.html): monotonic vs wall clock; wait vs wait_for cancellation, cancellation cleanup may outlast timeout.
- [Trio core](https://trio.readthedocs.io/en/stable/reference-core.html) and [testing](https://trio.readthedocs.io/en/stable/reference-testing.html): structured cancellation scopes, checkpoints, mock clock; no need to duplicate Protos structured ownership.
- [Go context](https://pkg.go.dev/context) and [time](https://pkg.go.dev/time): propagated deadlines and explicit cancellation, no need for a universal context object in Protos.
- [Tokio time](https://docs.rs/tokio/latest/tokio/time/index.html): sleep/absolute deadlines/timeout and test clock; Rust future-drop is not Protos shared-Future cancellation.
- [Erlang time and time correction](https://www.erlang.org/doc/apps/erts/time_correction.html) and [erlang BIFs](https://www.erlang.org/doc/apps/erts/erlang.html): monotonic timers, message delivery and cancellation races; no mandatory guest mailbox timer message.
- [Pony time package](https://stdlib.ponylang.io/time--index/): Actor-based timing service, useful capability comparison but mandatory broker would add coordination.
- [Node timers](https://nodejs.org/api/timers.html) and [ECMAScript Promise.race](https://tc39.es/ecma262/#sec-promise.race): host timing and explicit cancellation distinct from promise selection.
- [Java System.nanoTime](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/System.html#nanoTime()) and [ScheduledThreadPoolExecutor](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/concurrent/ScheduledThreadPoolExecutor.html): host time, delayed scheduling, cancellation and retention.
- [.NET TimeProvider](https://learn.microsoft.com/en-us/dotnet/api/system.timeprovider) and [Task.WaitAsync](https://learn.microsoft.com/en-us/dotnet/api/system.threading.tasks.task.waitasync): observation and provider abstraction distinct from producer cancellation.
- [WASI clocks](https://github.com/WebAssembly/wasi-clocks): explicit clock capability, monotonic subscriptions, wall/monotonic separation.
- [Swift Clock](https://developer.apple.com/documentation/swift/clock): distinct clock/suspend behavior; avoid over-specifying host sleep.
- [gRPC deadlines](https://grpc.io/docs/guides/deadlines/): propagation using remaining budget rather than a global synchronized monotonic epoch.
