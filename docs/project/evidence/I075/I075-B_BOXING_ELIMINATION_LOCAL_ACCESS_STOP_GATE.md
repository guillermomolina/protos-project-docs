## Observed failure mechanism

With `boxingEliminationTypes` enabled, the generated Bytecode DSL code used a
cached local tag when reading locals. In the failing run, the cached tag reached
an `ILLEGAL` state and the read through `LocalAccessor.getObject` raised
`FrameSlotTypeException`.

The reported failing stack reached:

```text
ReadFrameLocal.perform
  -> LocalAccessor.getObject
  -> FrameSlotTypeException
```

inside a generated continuation root after continuation resumption.

The exact generated-source line numbers are build artifacts and are not treated
as stable repository authority.

## Existing source-level warning

The published Protos HEAD already documents the relevant local-access invariant
inside `ProtosBytecodeRootNode.ReadFrameLocal`.

That operation deliberately uses `LocalAccessor` rather than generated
`LoadLocal`, because a local written only through the dynamic accessor API does
not participate in the frame-slot-kind speculation used by the DSL's own
`StoreLocal`/`LoadLocal` pair, and the source explicitly states that mixing
the two access mechanisms for the same local is not safe.

The current implementation also contains related access surfaces using:

- `LocalAccessor`;
- `MaterializedLocalAccessor`;
- `LocalRangeAccessor`;
- `ProtosFrameLexicalBindingAuthority`;
- frame-backed current lexical locals;
- captured/materialized lexical locals.

Therefore the failing behavior is not isolated to the selected internal
`int` metadata carrier. Enabling boxing elimination changes assumptions in the
generated local access machinery used by the existing Object-valued lexical
state.

## Why implementation stopped

Fixing the failure cannot be treated as a mechanical one-line follow-up.

The reported candidate repair surface includes at least:

- replacing or avoiding `LocalAccessor.getObject` for affected reads;
- reviewing `setObject`;
- reviewing `isCleared`;
- reviewing `MaterializedLocalAccessor` reads/writes;
- reviewing runtime `LocalRangeAccessor` access;
- reviewing `ProtosFrameLexicalBindingAuthority`;
- preserving execution-context local PRESENT/ABSENT semantics;
- preserving captured/materialized lexical access;
- preserving yield/continuation behavior;
- preserving uncached/cached execution behavior.

Those surfaces are exactly outside the authorized I075-B implementation
boundary.

No broader patch was attempted.
