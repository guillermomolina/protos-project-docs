## Captured frame-backed read authority

Slice 5 introduces an explicit `CapturedResolved` binding-resolution class for
references whose outer lexical owner and depth are statically proven while
remaining distinct from presence-ambiguous `Candidate` and fully `Dynamic`
references.

Eligible captured reads lower to `ReadCapturedFrameLocal`. The operation
addresses the already-retained materialized frame through the same
`ProtosFrameLexicalBindingAuthority` projected by the escaped
`ProtosExecutionContextValue`; it does not copy the binding value into Closure
state or another map.

Focused structural evidence inspected generated Bytecode instruction names and
demonstrated that a proven captured read actually contains the dedicated
`ReadCapturedFrameLocal` operation rather than merely obtaining the correct
result through generic lookup.

~~~text

~~~

## Captured writes and evaluation ordering

A proven captured bare assignment now resolves an ephemeral
`CapturedLexicalWriteTarget` before evaluating its RHS. When runtime topology
still matches the static proof, that target retains the exact frame-backed
authority and ordinal. If a nearer runtime binding already exists, or the
expected frame-backed authority cannot be used safely, resolution retains the
exact generic lexical destination instead.

After the RHS completes, `AssignCapturedFrameLocal` writes through that
previously selected target. The destination is not re-resolved after RHS
evaluation.

Focused evidence demonstrated both:

- ordinary captured mutation updates the same outer frame-backed binding; and
- if the RHS creates a same-name nearer binding after destination resolution,
  the write still targets the previously selected outer binding.

~~~text
PROVEN_CAPTURED_WRITE_USES_SINGLE_AUTHORITY=PASS
ASSIGNMENT_DESTINATION_BEFORE_RHS=PASS
CAPTURED_WRITE_BY_REFERENCE=PASS
~~~

## D179/C3 and fallback behavior

The direct captured path retains runtime presence guards for the current context
and every nearer captured context before the statically proven owner.

This preserves D179 candidate C3:

~~~text
nearer binding ABSENT
  -> proven outer binding remains reachable

nearer binding becomes PRESENT before a later access
  -> later read/write retargets to the nearer binding

destination resolved before RHS
  -> later RHS creation cannot retarget that already-resolved write
~~~

Coverage also retains the existing non-direct cases:

- a nearer statically declared but not-yet-PRESENT binding remains
  `Candidate` and uses ordinary fallback;
- `PRESENT(null)` remains semantically distinct from ABSENT;
- a truly `Dynamic` reference remains on the existing lookup/receiver path;
- writes do not acquire delegated mutation semantics.

## Reparse and Context-local rematerialization

Canonical analysis maps are intentionally keyed by AST identity. A fresh
parser/canonicalizer run therefore produces distinct nodes.

Slice 5 retains proven captured-site metadata across that boundary by remapping
only previously proven `CapturedResolved` accesses onto the fresh canonical
Closure using portable source-position/access-name metadata and a synthetic
copy of the owner's declared-name layout sufficient to preserve the stable
frame ordinal.

The remapped metadata contains no Truffle `Frame`, `BytecodeNode`,
`BytecodeLocal` or other Polyglot-Context-owned execution object in semantic
`ProtosClosureValue` state.

A focal reparse test first reproduced the loss of capture metadata as
`CapturedResolved -> Dynamic`, then demonstrated the repaired behavior:
fresh-AST rebuild retains `CapturedResolved`, emits `ReadCapturedFrameLocal`,
materializes the correct source section and executes successfully against the
original semantic Closure's captured lexical contexts.
