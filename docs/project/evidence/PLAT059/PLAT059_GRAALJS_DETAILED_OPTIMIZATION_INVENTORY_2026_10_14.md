## Audit boundary

GraalJS does **not** expose one monolithic `Lowerer` analogous to a conventional static compiler pass. The relevant sites are `GraalJSTranslator` (parser IR → Truffle nodes), `NodeFactory`, static `create(...)` factories of node classes, and lexical environment/scope analysis. This inventory enumerates **65 previously identified mechanisms or variants**. They are **not 65 independent optimization passes**: some rows describe early constant folding, some constant-operand specialization, some structural/scope elimination, and some specialized constructions that are partially required by JavaScript semantics. Classification is intentionally explicit.

Classification: `FOLD` = statically compute/elide an operation; `SPECIALIZE` = choose more specific runtime node (not the same as a static result); `REWRITE/FUSE` = change the static node representation; `STRUCTURE/SCOPE` = avoid unnecessary physical syntax/frame machinery; `CALL/LITERAL/LOWERING` = select a specialized call, aggregate, or continuation representation. All depend on actual JavaScript semantic/admission conditions; examples are illustrative, not exhaustive identities.

The linked **file-level anchors** identify the implementation entry points inspected; they are not claims of exhaustive line-by-line proof for every secondary call chain.

## Confirmed boundaries and exclusions

- **Selective rather than universal folding.** The inspected `JSSubtractNode`, `JSDivideNode` and `JSModuloNode` `create(...)` paths did not establish a blanket two-literal folder comparable to admitted `JSAddNode`/`JSMultiplyNode` forms. Absence here does **not** prove Graal cannot optimize the eventual Truffle graph.
- **Constant conditions are not globally erased by `IfNode.create`.** Its observed explicit rewrite swaps negated conditions. Other specific simplifications occur in the translator (notably certain loops).
- **TDZ checks vs TDZ initialization are distinct.** Some lexical access checks can be simplified, but the broader initialization-elision path governed by `allowTDZOptimization()` remains disabled in the inspected source.
- **Optional/inactive features:** `OptimizeNoFallthroughSwitch` is disabled by default; it can lower eligible switches to if/else structures. `lazy-translation` is disabled by default. Neither is counted in the 65 active/default mechanisms.
- **Not found as a general pre-Truffle pass:** global/local inter-statement constant propagation, graph-wide CSE, CFG-based DCE, arbitrary function inlining, full algebraic normalization, or universal constant boolean branch elimination. These are bounded **search negatives**, not proof they never occur in Truffle/Graal compilation.
- **Instrumentation matters.** Certain apparently dead nodes must remain or be materialized for source tags/debuggable observability; a faster node path alone does not prove equivalent debug behavior.
- **State vs semantics:** constant literal `1 + 2`, stable local `let x=1; x+2`, and parameterized `f(x)=x+2` are different problems. The static folding/one-constant operators above do not establish a general lexical constant-propagation algorithm.

## Interpretation for Protos (not authorization)

These mechanisms support a **comparative** argument for early fact-based emission and partially known-operand specialization, but JavaScript numeric operators are not Protos' overridable D013 messages. Protos must preserve binding `PRESENT`/ABSENT, receiver/prototype lookup authority, Context/Prelude publication/invalidation, exact numeric semantics, Closure/ReturnHome/Task effects, source/debug observation, and the **independent Bytecode DSL Builder oracle** mandated by approved PLAT058. PLAT059 does not select any new architecture.
