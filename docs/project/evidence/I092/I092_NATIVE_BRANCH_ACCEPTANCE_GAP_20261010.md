## 1. Exact requested behavior: native implementation, ordinary guest semantics

For the eligible canonical standard selection of `true.ifTrue() { 1 }`, the physical Truffle/Bytecode DSL lowering must be a guarded **native branch** over the canonical receiver, followed by the selected inline callback body, **without** going through the generic prepared-call/structured-Boolean invocation protocol in the canonical hit. `false.ifTrue() { 99 }` must evaluate the argument expression once and short-circuit to canonical null without executing the callback. Every genuinely noncanonical, changed, ineligible or invalidated selection must retain the exact ordinary D013 send semantics through the generic fallback.

This is a **semantic/physical separation**: Protos source still specifies an ordinary overridable message; the compiler does not need to physically dispatch that message on a guarded canonical hit. The conditional branches emitted by the current generic Boolean machinery are **not sufficient** to establish the independently specialized native-control branch. Numeric parity with GraalJS/GraalPy is not an unconditional semantic acceptance threshold.

## 2. Verified implementation shortfall

At the pinned product commit:

1. `CanonicalToBytecodeLowerer.emitComposedSend` recognizes a candidate through `tryCompactCanonicalIfTrue`, executes `TryCompactCanonicalBooleanOne`, and obtains a `CompactCanonicalBooleanCall` on the fast hit.
2. The conditional fast and generic-miss branches **converge into the same `preparedCall` local before `emitPreparedInvocation(...)`**. This is the decisive source-level shortfall, not a hypothesis derived from node counts.
3. `emitPreparedInvocation` classifies the result with `IsStructuredBooleanCall`, calls `emitLocalBooleanInvocation`, and thereby uses the generic sequence `PrepareStructuredBooleanCall`, `StructuredBooleanHasCallback`, `PrepareInlineStructuredBooleanCallbackCall`, `AdmitsInlineLiteralCallback`, `FinishStructuredBooleanCallback`, and `CompleteClosureCall`. This generic sequence has a physical `beginIfThenElse`, but it is **still shared with the prepared invocation protocol**.
4. `ProtosBytecodeRootNode.CompactCanonicalBooleanCall` implements `PreparedClosureCall` behavior for the shared protocol; `PreparedBooleanCall.compactIfTrue` wraps the same canonical hit in a new prepared-Boolean carrier. The child may be direct and frame-compact, but its hot-path ownership remains attached to that shared dispatcher.
5. Existing `ProtosI092CompactBooleanTest` validates functionality (true/false, once-only argument evaluation, custom override, capture and ReturnHome), **not the absence of the generic protocol in the canonical generated bytecode path**.

**Interpretation:** The published implementation meaningfully shrank and simplified the invocation path, but did **not implement the exact independently dispatched native Boolean fast branch** required by the project owner. This is an I092 implementation-completion task; the prior release/benchmark evidence remains historically valid.

## 4. Approved completion slice (one coherent implementation)

**Slice:** `I092-NATIVE` (an implementation slice *inside* I092, not a new formal issue).  
**Code repository:** `guillermomolina/protos` only.  
**Required architecture:** after receiver/argument expressions are evaluated once, select exact canonical `ifTrue` under stable receiver/home/callback-`call` guards. On hit, execute a real `beginIfThenElse` with:
- `false` → canonical null;
- `true` → direct, eligible PLAT044 B-prime inline callback body and exact return/cleanup;
- **no intermediate `CompactCanonicalBooleanCall`, `PreparedBooleanCall`, generic `PrepareStructuredBooleanCall` or `emitPreparedInvocation` on this hit**;
- miss or ineligible → original complete `PrepareSendOne` / `emitPreparedInvocation` fallback.

Preserve the canonical Closure value's eager evaluation, identity and context/activation capture semantics, the existing lazy materialization where safe, source instrumentation, ReturnHome, exception/continuation/cancellation dynamics, override/shadow/alias/invalidation, and multi-Context isolation. Reuse existing `emitInlineLiteralCallback` and PLAT044 B-prime frame-native facilities if their carrier/cleanup contracts can be met without reintroducing the generic Boolean dispatcher. Avoid new universal activation/Task/root carriers. Do not change `ifFalse`, `whileTrue`, other generic Boolean methods, language semantics or benchmarks.

**Structural acceptance tests are essential:** verify the canonical generated Bytecode DSL emission has an independently handled native fast branch, which bypasses the named generic structured-Boolean operations, while the miss branch retains exact generic semantics. Test successful canonical and invalidated/overridden paths and tooling/ReturnHome; retain existing broad test coverage. No new perf claim before a subsequent changed-product graph capture.

**Human executor discipline:** agent edits source/tests, does not run tests/builds/git mutations; human performs focused and impact-policy full validation, then only after green tests finalizes `pom.xml` and root `CHANGELOG.md`, commits/pushes product. No tests after metadata bump without a meaningful code/dependency change. After product publication, only the human separately captures the necessary graph cases through the unchanged benchmark harness to confirm source-level acceptance in IR. Previous measurements must not be rerun without changed product bytes.
