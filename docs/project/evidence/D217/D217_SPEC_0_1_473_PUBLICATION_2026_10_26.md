## Published normative delta

The D217 product commit contains a new `spec/PROTOS_SPEC_CHANGELOG.md` entry and these normative owners:

- [`spec/io/NETWORK.md`](https://github.com/guillermomolina/protos/blob/5f95dc086fc9bc853afb712915db47ab28547417/spec/io/NETWORK.md): `listener.acceptCapability() -> TcpAcceptor` synchronously derives an acceptance-only capability from one existing logical listener; `acceptor.accept() -> Future<TcpConnection>` participates in that listener's concurrent acceptance domain. No new socket, listener, Network authority, global/Prelude constructor or public placement API.
- [`spec/concurrency/ACTORS.md`](https://github.com/guillermomolina/protos/blob/5f95dc086fc9bc853afb712915db47ab28547417/spec/concurrency/ACTORS.md): explicit same-Process `Actor.spawn` initialization-argument delegation validates the actual transferred graph atomically, preserves the original restrictions on `Network`, `TcpListener` and `TcpConnection`, and leaves `send()`/`request()` outside the delegation contract.
- [`spec/io/PROCESS_IO.md`](https://github.com/guillermomolina/protos/blob/5f95dc086fc9bc853afb712915db47ab28547417/spec/io/PROCESS_IO.md): distinct Actor-local representations can share one logical listener's acceptance domain without guest-Actor mediation; unrelated listeners retain independent domains.

The owner expressly approved **option A** for delegated wrapper state: delegation conveys **only acceptance authority**. Source-added local slots and source `OPEN`/`CLOSED`/`FROZEN` state are not copied, traversed or shared. The destination receives a fresh, structurally `OPEN` `TcpAcceptor` with the standard frozen protocol parent. Ordinary enclosing argument graphs retain their normal validation rules; no values reachable exclusively through source capability slots are traversed by this special provisioning. Inherited `Object.close()` on an acceptor affects only its structural state, not the logical TCP listener.

A post-close `acceptCapability()` signals `IOLifecycleError` synchronously. A post-close `acceptor.accept()` returns a **fresh failed ordinary Future** carrying a fresh `IOLifecycleError`. Listener close and cancellation use existing `IO_CORE.md` cutovers, retain already delivered connections and require safe release of accepted-but-undeliverable host resources.

## Invariant/delta and human executor checkpoint

- **GITHUB021: preserved.** Explicit Network/listener authority; no automatic transfer of a live `TcpListener` or `TcpConnection`; no mutable cross-Actor guest alias; no cross-Process proxy/RPC/socket migration; compatible same-Process Actor admission; no mandatory central guest Actor or guest message per accept; pay-as-you-grow; and D215/LIB025 single-request HTTP behavior untouched.
- **Approved addition only:** a new, attenuated, spawn-delegable accept-only capability, with exactly one logical listener per acceptor and no global fairness/order guarantee.
- **Maintainer report:** D217 commit **pushed**, `git diff --check` **clean**, **all local tests PASS**. This record does not claim independently executed validation, build logs, benchmark results, CPU scaling, or implemented `TcpAcceptor` runtime.
- **Publication identity verified:** GitHub returns the exact D217 commit with the `0.1.473` specification changelog entry and the normative file delta.

## Remaining independent work

D217's **design and normative publication** are complete, but this specification-only commit does not implement the new runtime capability. A separately tracked **Ixxx implementation** must follow the ratified normative contract before applications can use `TcpAcceptor`.

D216 already has owner-selected **Option B** (optional reusable `std:http` continuous hosting), but the exact hosting API, admission bounds, shutdown/drain, failure/lifetime rules and corresponding independent owner approval remain open. Its runtime implementation is not authorized until that separate contract is normatively ratified.

Historical comparative research at [D216/D217 checkpoint](../D216/D216_TCP_ACTOR_ACCEPTOR_M3_LOCAL_RESEARCH_2026_10_25.md) remains pinned to the older `0.1.472` baseline and must not be rewritten as though it described the later publication.
