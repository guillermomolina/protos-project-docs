## Verified source changes in the published diff

The published I115 checkpoint combines:

1. **Captured Closure Prelude admission:** cache Prelude identity on admitted compact Closure calls; retain current caller-inheritance and general fallback when capture is not an admissible proof.
2. **Lexical selection:** cache values from exact ordinary materialized FROZEN owners; cache missing nearer bindings only under the actual, stable map-backed authority/store identity and a Shape absence guard. Mutable, deferred, frame-backed, shadowed or replaced authorities must continue through ordinary live resolution.
3. **Standard Array construction and indexing:** eliminate redundant structural-selection rechecks when selected owners are proven FROZEN, without removing mutable-receiver or inherited-selection invalidation. Keep independently allocated Arrays for each evaluation and dynamic noncanonical factories.
4. **Array/Bytes index/error paths:** use `Long.compareUnsigned(index, size)` for signed-64 negative/out-of-bounds rejection before narrowing to host `int`; profile exceptional cases with Truffle `InlinedBranchProfile` while retaining guest Error behavior and frozen-write validation.
5. **Numeric and String selection regressions:** extend tests for canonical behavior, dynamic overrides and fallback; refresh `tools/java_generated_bytecode_bci_pe_baseline.json` to the published generated Bytecode DSL topology.

The change **does not** authorize unconditional direct bypass of message selection, loss of slot mutation/shadowing behavior, additional guest primitive types, or a new lexical binding authority.
