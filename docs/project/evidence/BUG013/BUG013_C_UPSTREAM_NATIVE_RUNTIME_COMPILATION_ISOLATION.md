# BUG013-C — Residual Native runtime-compilation isolation

Status: **DIAGNOSIS CLOSED; BUG013 REMAINS OPEN**

This durable, non-normative record retains the BUG013-C diagnosis for
`guillermomolina/protos#749`.

It does not define Protos language or Standard Library semantics.

BUG013-A found and BUG013-B repaired a real Protos-owned raw-`VirtualFrame`
lifetime violation. BUG013-C investigates the residual failure that remains when
the maintained Native guest Tier-2 workload is strong enough to exercise the
current generated Bytecode DSL path.

## Hardened Protos Native observation

The former maintained forced-JIT workload was only:

```text
-e '1'
```

That workload could report a misleading partial green because it did not force
the helper/generated roots through a sufficiently hot cached path.

A stronger workload using a captured value and repeated closure calls:

```protos
x: 1
f: () => { x }
f()
... repeated sufficiently to make the root hot ...
```

produced, on the current Native line, the characteristic failure:

```text
NATIVE_FORCED_JIT_STATUS=0
OPT_FAILED=2
FRAME_WITHOUT_BOXING_FAILURES=6
COMPILATION_FAILURES=0
HELPER_BYTECODE_ROOT_TIER2=0
SEMANTIC_BYTECODE_ROOT_TIER2=0
NATIVE_FORCED_GUEST_JIT=FAIL_OPT_FAILED
```

The process status remains zero because `CompilationFailureAction=Print` allows
guest execution to continue after the compiler bailout. The maintained gate
therefore must inspect compilation evidence rather than process status alone.

## Protos-local alternatives that were ruled out

Bounded Protos experiments did not remove the residual bailout.

The failure remained when independently testing or removing the following
candidate causes:

- I075 integer boxing elimination;
- I074 uncached-interpreter adoption together with I075;
- I073/I074/I075 together;
- semantic-root `VirtualFrame` binding;
- the compact ordinary-send ABI;
- the frame-backed lexical fast path;
- `CompileImmediately` versus ordinary threshold-triggered compilation.

Those experiments were not retained as product changes.

The BUG013-B lifetime repair remains correct and must not be reverted merely
because a separate residual compiler failure exists.

## GR79495 backport result

Two later upstream fixes associated with GR79495 were tested as an exact local
backport on the adopted 25.4.4.1.1 plane:

- `9f2d0364e8c1fe83d4be302c48808869fd864bda` —
  `Fix: explode copyTo in compiled code`;
- `4473f2aba25ec57995abcbd260ce4645989a67ad` —
  `Fix: clear return value from frame before returning`.

The patched API and generated sources were verified active, including the
generated compiled-code result-slot clear. Native Image still failed with the
same `FrameWithoutBoxing should not be materialized` bailout.

Therefore those fixes are insufficient for the BUG013 residual.

## Independent minimal reproducer

BUG013-C then removed Protos from the experiment entirely.

A standalone temporary Maven project defined a tiny Truffle language and a
generated Bytecode DSL root. The first variant used
`@GenerateBytecode(enableYield=true)`; a second control root used
`enableYield=false` and declared no custom operations.

The `enableYield=false` root executes only the semantic equivalent of:

```text
return 1
```

Its generated entry still contains the ordinary Bytecode DSL boundary:

```java
state = bc.continueAt(this, frame, state);
```

### Native result

The standalone image built successfully with the coherent
`25.5.5-SNAPSHOT` plane and Truffle runtime compilation support enabled.

Both the yield-capable constant root and the plain `enableYield=false` root
failed Tier 2 in Native Image:

```text
MiniRootGen      -> opt failed -> FrameWithoutBoxing should not be materialized
MiniPlainRootGen -> opt failed -> FrameWithoutBoxing should not be materialized
```

The plain root still returned the correct interpreted result:

```text
REPRO_RESULT=1
```

so process success is not compiler success.

### JVM control

The exact same `MiniPlainRootGen`, with the exact same
`25.5.5-SNAPSHOT` dependency plane, compiled successfully on the JVM:

```text
MiniPlainRootGen |Tier 2| ... opt done
MiniPlainRootGen |Tier 2| ... opt done
REPRO_RESULT=1
```

No `FrameWithoutBoxing` bailout was observed.

in Protos semantics or the repaired BUG013-B lifetime boundary.

## Relationship to recent Protos I07x work

This upstream ownership result does **not** imply that Protos must wait while
remaining broken.

Protos previously produced a working Native Image before later implementation
work adopted Bytecode DSL configurations/paths that now exercise this upstream
failure. A Protos-side compatibility mitigation may therefore consist of
removing or narrowing the most recent implementation adoption that made the
broken upstream path mandatory.

That is a separate question from upstream ownership:

```text
UPSTREAM_DEFECT_EXISTS=YES
PROTOS_CURRENTLY_EXERCISES_DEFECT=YES
PROTOS_MAY_AVOID_DEFECT_WITHOUT_WEAKENING_NATIVE_GATE=TO_BE_ESTABLISHED
```

The next Protos work should identify the smallest recent I07x implementation
rollback/narrowing that restores the previously operational Native path while
preserving the strong Native admission test. It should not search old GraalVM
versions as a substitute for that Protos compatibility decision.

## Maintained Native gate consequence

The historical `-e '1'` workload is insufficient as release authority.

The maintained Native test must preserve a hot workload that:

- reaches the relevant generated Bytecode DSL cached/runtime-compilation path;
- fails on any `opt failed` line;
- fails on any `FrameWithoutBoxing` materialization bailout;
- requires successful Tier-2 evidence for both helper and semantic generated
  roots; and
- does not infer compiler PASS from process status zero.

This hardening is a test-authority correction, not a workaround for the
upstream defect.
