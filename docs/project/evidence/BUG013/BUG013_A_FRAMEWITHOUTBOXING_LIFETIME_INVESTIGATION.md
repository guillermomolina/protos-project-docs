## Primary finding

The primary failure owner is Protos.

At current HEAD, `ProtosBytecodeRootNode.InstallFrameLexicalAuthority.perform`
receives:

```java
@Bind("$frame") VirtualFrame frame
```

and passes that unmaterialized frame into a newly allocated
`ProtosFrameLexicalBindingAuthority`.

That authority stores the value in its `frame` field. The authority is then
retained from `ProtosActivation.deferredContextAuthority`. Only later, if
`ProtosActivation.context()` makes the execution context guest-observable,
`prepareForContextObservation()` calls:

```java
frame = frame.materialize();
```

The order is therefore:

```text
VirtualFrame acquired
  -> stored by ProtosFrameLexicalBindingAuthority
  -> authority stored by ProtosActivation
  -> only later frame.materialize()
```

This violates the Truffle frame lifetime contract before the deferred
materialization is reached.

## Upstream 25.4.4.1.1 authority

The exact upstream tag inspected was:

```text
oracle/graal@graal-25.4.4.1.1
```

The relevant Truffle API contract is explicit:

- `VirtualFrame` instances must not be stored in a field or cast to
  `java.lang.Object`;
- when such an escape is necessary, the frame must first be converted using
  `VirtualFrame.materialize()`;
- `MaterializedFrame` is the frame representation permitted to be stored in
  fields or cast to `Object`.

The relevant source surfaces inspected include:

```text
truffle/.../frame/VirtualFrame.java
truffle/.../frame/MaterializedFrame.java
truffle/.../frame/Frame.java
truffle/.../impl/FrameWithoutBoxing.java
compiler/.../nodes/virtual/EnsureVirtualizedNode.java
compiler/.../truffle/nodes/frame/NewFrameNode.java
compiler/.../truffle/substitutions/TruffleGraphBuilderPlugins.java
truffle/.../bytecode/GenerateBytecode.java
truffle/.../bytecode/LocalAccessor.java
truffle/.../bytecode/LocalRangeAccessor.java
truffle/.../bytecode/MaterializedLocalAccessor.java
```

`FrameWithoutBoxing.materialize()` is supported. Truffle compiler plugins
explicitly model materialization through the materialization path rather than
prohibiting it.

The diagnostic:

```text
FrameWithoutBoxing should not be materialized
```

comes from the compiler's `EnsureVirtualized` invariant when an object that
was required to remain virtual is forced to materialize or escape. It is not an
API statement that `Frame.materialize()` is forbidden.

Upstream tests combine uncached interpretation with yield and boxing
elimination, so that feature combination is not by itself evidence of an
unsupported configuration.

### I075

```text

```

```text

```

and repaired a separate stale-`BytecodeNode` problem by resolving the
declaring root's current node for frame-backed local access.

Boxing elimination may affect when or how the invalid escape becomes visible to
partial evaluation, but removing it would not repair the underlying violation:
the raw `VirtualFrame` would still be retained before materialization.

Upstream Bytecode DSL tests cover boxing elimination together with uncached
execution, yield and materialized-local machinery.

### Continuations

```text
CONTINUATION_CAUSAL_ROLE=NOT_CAUSALLY_REQUIRED
```

The reproducer used to establish BUG013 can be continuation-free at the guest
level. Upstream also contains explicit coverage of materialized frames across
uncached-to-cached transitions.

Continuation/yield machinery therefore remains relevant surrounding runtime
machinery, but no evidence establishes it as the primary cause of the invalid
frame lifetime.

### Native Image

```text
NATIVE_IMAGE_CAUSAL_ROLE=EXPOSING_COMPILATION_ENVIRONMENT_NOT_PRIMARY_OWNER
```

Native execution uses the Substrate Truffle runtime/compiler and its runtime
partial-evaluation path. That environment exposes the invalid escape as an
`EnsureVirtualized` failure.

The ordinary JVM compiler accepting the current source shape does not make that
shape supported. The same source violates the Truffle `VirtualFrame` contract
independently of which compiler happens to diagnose it.

No missing Protos Native hosted/runtime configuration requirement and no
upstream unsupported-combination requirement was established.

Relevant upstream tests inspected at the exact 25.4.4.1.1 tag include:

## Smallest repair boundary

The smallest correct repair is repository-local and does not require a new
platform or language decision.

```text
SMALLEST_REPAIR=
  materialize the current frame before it is passed into/stored by
  ProtosFrameLexicalBindingAuthority;
  retain only MaterializedFrame in that authority;
  stop using deferred prepareForContextObservation() as the point that first
  makes the retained frame escape-safe
```

The intended bounded implementation shape is:

```text
InstallFrameLexicalAuthority.perform(...)
  VirtualFrame frame
    -> frame.materialize()
    -> construct ProtosFrameLexicalBindingAuthority with MaterializedFrame

ProtosFrameLexicalBindingAuthority
  frame field:
    VirtualFrame mutable
      -> final MaterializedFrame

prepareForContextObservation()
  no longer performs first-time frame materialization
```

Materialization should occur at the explicit escape boundary rather than after
passing the raw `VirtualFrame` through an ordinary object constructor. This
avoids depending on compiler inlining to make an otherwise-invalid lifetime
safe.

## Remaining uncertainty

The investigation does not establish the exact graph node by which the same
diagnostic becomes visible while compiling
`ProtosSemanticBytecodeRootNodeGen`.

That uncertainty does not block the bounded repair because:

1. the helper root also fails;
2. the current helper-root path contains an explicit violation of the upstream
   `VirtualFrame` lifetime contract; and
3. the maintained Native regression will independently require successful
   Tier-2 compilation of both helper and semantic roots after the repair.

If the semantic root still fails after the established helper-frame lifetime
violation is fixed, that would be evidence of a second defect rather than a
reason to leave the known violation in place.
