## Normative boundary reconciliation

- [IO_CORE.md:314–435](https://github.com/guillermomolina/protos/blob/1afc4ceeb4b6df9878fb2d2f168235277f8e7e70/spec/io/IO_CORE.md#L314-L435): close has permanent cutover, uncommitted operations fail, committed aftermath is preserved, one logical release and stable Error identity. Failed close transfers residual custody to implementation/host; no guest retry or blind native retry on potentially reused identity. Proposed clarification consistent with D270-D: abort after successful close observes success without new release; after failed close observes the recorded same-domain Error without new release. Close after abort observes the same logical retirement. Explicit abort during pending close is the intentional new delta; no ordinary-close change without abort.
- [BYTE_IO.md:550–658](https://github.com/guillermomolina/protos/blob/1afc4ceeb4b6df9878fb2d2f168235277f8e7e70/spec/io/BYTE_IO.md#L550-L658): shutdownRead commits null for previously admitted uncommitted reads; later whole-resource abort cannot rewrite committed null or prior cancellation/result. Abort first rejects later open-only shutdown. Pending shutdownWrite with failed preceding output cannot claim clean frontier; committed successful or failed directional outcomes remain stable. Do not implement abort as shutdownRead + shutdownWrite + close. Reconcile exact pending directional release and follower precedence.
- [TLS.md:280–350](https://github.com/guillermomolina/protos/blob/1afc4ceeb4b6df9878fb2d2f168235277f8e7e70/spec/io/TLS.md#L280-L350): authenticated close_notify establishes clean EOF; physical EOF without it is TlsError kind truncated; an actual underlying transport Error is preserved instead of converted to TlsError. ## Race and falsification obligations

- First effect in flight at abort: zero with earlier valid cancellation preserves cancelled; zero with abort winning fails IOLifecycleError; positive incomplete prefix fails IOError without rollback; already committed final success/failure remains unchanged. Later effect attempts after commitment require the same abort admission frontier. Clarify full in-flight final contribution versus final result commitment and independent error precedence before ratification.
- Close/abort followers: one release and one recorded outcome, no success from physicalClosed alone, no new release after failed close, no duplicate callback, no resurrection, descriptor/channel reuse safety.
- Half-close: prior committed null preserved; pending output shutdown cannot succeed after failed required writes; abort-first rejects new open-only work; settle required directional aftermath.
- Actor termination: authorized cleanup only; host-only retirement if owner is gone, no re-entry of ordinary guest work. Process termination has existing authority revocation and custody boundaries.
- TLS transport error preservation vs unauthenticated EOF; HTTP Host cooperative abort remains unchanged; safe quota retention and mandatory cleanup failure classification.
- Deterministic first-effect and later-effect race tests, physical close flag vs actual completion/failure, poller stop/fallback race, late callbacks, directional followers, domain termination and nonreading real peer; JVM and installed Native Linux x86_64 CLI. Existing tests located via source search include ProtosTcpConnectionFoundationTest, ProtosTcpConnectionDuplexLifecycleTest, ProtosTcpConnectionIntegratedConformanceTest, ProtosNioTcpConnectionWriteTest, ProtosNioTcpConnectionLifecycleTest, ProtosNioTcpConnectionReadTest, ProtosTerminationCleanupCloseTest and ProtosTcpConnectionEndpointObservationTest. Test contents/execution not certified by this review. No ARM target.
