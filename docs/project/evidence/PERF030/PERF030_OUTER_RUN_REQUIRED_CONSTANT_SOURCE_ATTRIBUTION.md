## LocalRangeAccessor contract is wider than the ordinal

The decisive source finding is that GraalVM 25.4
`LocalRangeAccessor` does not assert PE constancy only for its integer offset.

Its local-access methods invoke `CompilerAsserts.partialEvaluationConstant`
for three separate values:

```text
1. this             -- the LocalRangeAccessor instance
2. bytecodeNode     -- the BytecodeNode supplied to the access
3. offset           -- the LocalRangeAccessor range index
```

The exact Graal authority is:

```text
truffle/src/com.oracle.truffle.api.bytecode/.../LocalRangeAccessor.java
blob=07addc390d2c6a755ab3d30e5494e08cb99fc2e1
```

Consequently, the PERF030-O JFR message:

```text
Partial evaluation did not reduce value to a constant,
is a regular compiler node: 36664|Pi
```

does **not** prove that the failing value is the `ordinal` / `offset`.
It may instead represent the accessor receiver, the current
`BytecodeNode`, the offset, or another required-constant assertion reached in
the same outer root.

The Graal PE constant plugin confirms that the bailout text is constructed from
the failing compiler `ValueNode`; the text does not encode the Java source
argument that supplied it.

Exact authority:

## Static guard model

The checked-in `tools/java_local_range_pe_guard.py` performs a backward,
interprocedural positional-provenance analysis for the **integer local index**.

For a sink whose index is a method parameter, it follows caller arguments.
When the chain reaches an `@Operation` specialization and the corresponding
parameter is proven to be an `int @ConstantOperand`, the terminal provenance
is classified as:

```text
PE_CONSTANT_FROM_OPERATION
```

A sink is `PE_REACHABLE_PROVEN_CONSTANT` only when all resolved PE-root
terminal provenances for that tracked integer index are constant.

This means the guard's proof is materially narrower than the complete
`LocalRangeAccessor` runtime compilation contract:

```text
GUARD_PROVES=LOCAL_RANGE_INTEGER_INDEX_PROVENANCE
GUARD_DOES_NOT_PROVE=LOCAL_RANGE_ACCESSOR_RECEIVER_PE_CONSTANT
GUARD_DOES_NOT_PROVE=CURRENT_BYTECODE_NODE_PE_CONSTANT
```

The representative call chain stored in the reachability baseline is not an
independent proof that only that one caller reaches a shared sink. The guard
walks the resolved callers and classifies the tracked index across the reachable
PE roots.

The gap is therefore not established to be a bug in ordinary Java parameter
propagation of the ordinal. It is a mismatch between a guard described as
proving LocalRange PE safety and the wider set of required constants enforced by
the actual `LocalRangeAccessor` API.

```text
STATIC_GUARD_MODEL_SOUND_FOR_INTEGER_INDEX=YES
STATIC_GUARD_MODEL_COMPLETE_FOR_LOCAL_RANGE_ACCESS=NO
GUARD_REPAIR_REQUIRED=YES
```

A future guard repair should either:

- extend the safety proof to cover accessor receiver, current BytecodeNode and
  offset; or
- explicitly rename/reframe the existing proof as index-only and add a separate
  authority for the other required constants.

No guard implementation is performed by PERF030-P.

## Candidate classification

### A. Generated Bytecode DSL loses the primitive constant operand

```text
CLASSIFICATION=NOT_SUPPORTED
```

The source contract and generated representation preserve the
`int @ConstantOperand` as an inline constant instruction operand.

### B. Ordinary Java helper propagation loses the ordinal

```text
CLASSIFICATION=UNRESOLVED
```

The static guard assumes positional propagation across ordinary Java helper
parameters, and no source evidence found here disproves that assumption.
PERF030-O does not identify the failing value as the ordinal, so the runtime
failure cannot be used as proof that this propagation rule is false.

### C. Branch / fallback merge poisons the ordinal

```text
CLASSIFICATION=POSSIBLE_BUT_NOT_PROVEN
```

A Graal `Pi` node can arise from type/value refinement around branches, but
the token `36664|Pi` is not enough to map the node to the ordinal, an authority
receiver, a BytecodeNode, or a specific branch.

### D. LocalRangeAccessor requires additional PE constants

```text
CLASSIFICATION=PROVEN
```

This is directly established by GraalVM 25.4 source.

### E. A distinct required-constant assertion in the same root fails

```text
CLASSIFICATION=CANNOT_BE_EXCLUDED
```

The JFR failure token alone cannot distinguish the LocalRange assertions from
another required-constant assertion reached during partial evaluation.
