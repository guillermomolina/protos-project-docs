## Minimum reproducer

The published reproducer uses a standalone language, without Protos code, custom operations, or custom instrumentations. The relevant root annotation is:

```java
@GenerateBytecode(
    languageClass = EmptyLanguage.class,
    enableInstructionTracing = false
)
public abstract static class EmptyRoot
        extends RootNode implements BytecodeRootNode {

    protected EmptyRoot(EmptyLanguage language, FrameDescriptor descriptor) {
        super(language, descriptor);
    }
}
```

The builder emits **only**:

```java
b.beginRoot();
b.endRoot();
```

No explicit return or constant is emitted; the DSL's implicit generated bytecode is `load.null; return`. The standalone Maven project uses `org.graalvm.truffle:truffle-api`, `truffle-runtime`, and annotation processor `truffle-dsl-processor` at exactly `25.4.4.1.1`, with Java compiler release 21.

Reproduction, run inside the unpacked external attachment:

```bash
mvn -q -DskipTests clean compile
```

### Observed compile boundary

```text
DEFAULT_BUILD_RETURN_CODE=0
NO_TRACING_BUILD_RETURN_CODE=1
GENERATED_CALL_PRESENT=True
GENERATED_METHOD_DEFINITION_PRESENT=False
REPRODUCED=True
```

The captured Maven diagnostic states:

```text
[ERROR] .../generated-sources/annotations/diagnostic/EmptyRootGen.java:[322,28] cannot find symbol
  symbol:   method publishOldBytecodes()
  location: variable oldBytecode of type diagnostic.EmptyRootGen.AbstractBytecodeNode
```

In the failing generated Java, `oldBytecode.publishOldBytecodes()` is emitted; the generated `AbstractBytecodeNode` does not define it. Recompiling the same project with instruction tracing left enabled succeeds and its generated `AbstractBytecodeNode` includes the method.

### Candidate source explanation, not an accepted upstream fix

Current public upstream generator code suggests that `BytecodeDSLModel.isBytecodeUpdatable()` becomes false when tracing and all instrumentation are disabled, causing `AbstractBytecodeNodeElement` to omit the method while `BytecodeRootNodeElement.createUpdateBytecode()` still emits its call. This source-level explanation was not verified against a checked-out tagged source tree for the exact Maven processor revision. The released-processor **observed failure** is independently verified; the precise generator patch and latest-snapshot behavior are not.
