## Decisive implementation fact

I068 already implements stable lexical identity and semantic presence as
separate concepts.

For statically admitted current bindings,
`ProtosFrameLexicalBindingAuthority` stores the guest value in Bytecode DSL
frame locals and derives semantic presence from
`LocalRangeAccessor.isCleared(...)`.

Its current `removeBinding(name)` implementation already clears a frame-backed
local with `LocalRangeAccessor.clear(...)`. The stable name/layout/ordinal is
not removed.

Truffle's exact source implements these operations as frame-local state:

```text
LocalAccessor.clear / LocalRangeAccessor.clear
    -> BytecodeNode.clearLocalValueInternal(...)
    -> frame.clear(frameIndex)

isCleared(...)
    -> frame.getTag(frameIndex) == FrameSlotKind.Illegal.tag
```

The accessors, Bytecode node and range offsets are asserted as partial-evaluation
constants by the Bytecode DSL API.

Therefore restoring:

```text
PRESENT -> ABSENT -> PRESENT
```

does not require destruction/recreation of lexical identity, a new presence
bitmap, a guest-value sentinel, or migration of static bindings back to a
String-keyed map.

## Exact C3 dependency that must be removed

The C3 implementation adds a semantic rejection in
`ProtosExecutionContextValue.removeLocalSlot(name)`: a PRESENT execution-context
slot cannot reach the authority's existing removal path.

I068 also optimizes a statically `Resolved` current read through
`ReadFrameLocal` without a presence check. That optimization is correct only
while C3 guarantees that an already-PRESENT current binding can never become
ABSENT.

C0/E requires:

```text
current static Resolved read:
    if frame local PRESENT:
        direct frame read
    else:
        exact lexical/receiver fallback
```

No layout mutation is required.

## Captured contexts

The captured path already establishes the architectural feasibility.

`ReadCapturedFrameLocal`:

1. checks the current context for a nearer PRESENT binding;
2. checks nearer captured contexts;
3. locates the statically proven owner;
4. accepts the direct frame-native owner path only when
   `hasFrameBackedBindingAt(name, ordinal)` is true;
5. otherwise performs the exact existing lexical fallback.

A removal on the owning escaped/captured context clears that same authority's
retained frame slot. Later Closure reads therefore observe ABSENT and continue
through the normal chain without any captured-value copy.

```text
CAPTURE_BY_REFERENCE_PRESERVED=YES
ESCAPED_CONTEXT_OBSERVES_REMOVAL=YES
NO_CAPTURED_VALUE_COPY=YES
```

## Assignment ordering

Captured assignment already resolves and retains its exact destination before
RHS evaluation through `ResolveCapturedWritableLexicalTarget`, then writes
through `AssignCapturedFrameLocal`.

Under restored C0, if RHS effects remove the selected destination, the
subsequent write must fail on that exact previously selected destination. It
must not re-run lexical lookup and retarget the assignment. This preserves the
existing normative assignment-destination-before-RHS rule.

## Presence/value separation

Candidate E preserves:

```text
PRESENT(null)
    frame local PRESENT
    value = ProtosNullValue.INSTANCE

ABSENT
    frame local CLEARED
```

No host-null or internal sentinel is needed to represent semantic absence.

## Reflection and debugger

`bindingsSnapshot()` already omits a cleared frame-backed local and includes
PRESENT frame-backed bindings plus dynamic overflow.

`ProtosDebuggerScope` obtains local names from semantic
`localSlotsSnapshot()` and reads through the exact lexical fallback. Therefore
a removed local naturally disappears from the current scope projection and an
outer lexical/receiver value may become visible under restored C0.

## Candidate comparison result

The reconsideration compared:

```text
A = keep C3
B = separate presence bitmap/cell
C = internal UNBOUND sentinel
D = move removable static bindings out of DSL locals
E = existing frame-native cleared presence
```

Candidate E was recommended and owner-approved because it:

- preserves C0 completely;
- preserves stable static identity/layout;
- preserves the frame-backed single value authority;
- uses presence state that already exists in the Bytecode frame;
- preserves materialized/captured access;
- preserves reflection/debugger projection;
- introduces no sentinel;
- introduces no second authoritative store;
- requires no broad `@TruffleBoundary`;
- does not reintroduce generic map/name lookup on the normal PRESENT fast path.
