## Scope of the problem and provenance restrictions

The target is the **complete physical path** for a fresh one-argument source Closure, including creation, binding, root entry, lookup, dispatch, selected direct/indirect call, generic fallback, capture and result/error/continuation completion.

Canonical benchmark:
- [Protos primitive-closure-call](https://github.com/guillermomolina/protos-benchmarks/blob/main/truffle/workloads/primitive-closure-call/primitive-closure-call.protos): `run: () => { identity: (value) => { value } identity(1) }`
- [GraalPy counterpart](https://github.com/guillermomolina/protos-benchmarks/blob/main/truffle/workloads/primitive-closure-call/primitive-closure-call.py): a `run` function creates a new inner `identity` function on each invocation.
- An alternative two-statement bare Protos source `identity: (value) => { value }\nidentity(1)` is **not** interchangeable with the wrapped benchmark for whole-graph comparisons.

Historical, matched `After TruffleTier` selected graphs: Protos **4,533** and GraalPy **50** nodes (~90.7x) at an older Protos revision, with source and framework conditions recorded in [PERF042/#871](https://github.com/guillermomolina/protos/issues/871) and benchmark data. The bare-source local 4,804/4,970-node observations were experimental, prior to the 0.3.376 cleaned publication and **not same-root clean-current-HEAD benchmark evidence**. Counts of nodes by source ancestry overlap and do **not** prove hot reachability, survival under a proposed patch or 99% removability. The owner's «~110x» and «remove 99%» language specifies the desired correction scale, not an established source-to-IR causal fraction.

I112's 11+5 = 16 **FULL Bytecode instructions** across two roots is a separate metric from surviving optimized Graal IR nodes. Do not conclude compilation convergence from this number.

## Verified source-level call chain (precise anchors)

### 1. Protos: emission and specialized normal branch

1. [`CanonicalToBytecodeLowerer.java` around lines 3950–4090](https://github.com/guillermomolina/protos/blob/edcb758fadb0e749cd45711cd664044d0b6db6bd/src/main/java/com/guillermomolina/protos/execution/bytecode/lowering/CanonicalToBytecodeLowerer.java#L3950-L4090): `admitsTerminalClosureCall` checks immutable NORMAL profile, terminal expression shape, operand admissibility, inline candidates and activation/inline-callback state. `emitTerminalClosureCall` emits `InvokeClosureOneTail` for one supplied argument with source/CallTag and no explicit caller Bytecode operand. This implementation is PLAT062-T's approved specialized/fused operation, **not** an anti-pattern to remove simply because GraalPy uses a separate return.
2. [`ProtosBytecodeRootNode.java` lines 9710–9970](https://github.com/guillermomolina/protos/blob/edcb758fadb0e749cd45711cd664044d0b6db6bd/src/main/java/com/guillermomolina/protos/execution/bytecode/activation/ProtosBytecodeRootNode.java#L9710-L9970): `InvokeClosureOneTail` has `guardedSource`, `definitionSource`, `rejectedSource`, `generic` plus `enterDirect` and `prepareAndEnter`. Both direct variants call a `DirectCallNode` with the full compact B5 Call1 arguments; they then call `ProtosTailCallContinuation.completeOrDefer`. The generic path prepares and enters one ordinary selected invocation.
3. [`ProtosBytecodeRootNode.java` lines 9250–9475](https://github.com/guillermomolina/protos/blob/edcb758fadb0e749cd45711cd664044d0b6db6bd/src/main/java/com/guillermomolina/protos/execution/bytecode/activation/ProtosBytecodeRootNode.java#L9250-L9475): the `definitionSource` caches `CanonicalClosure`, `ProtosClosureExecutionPlan`, entered Context, projection flag and derived target, with bounded PIC. Yet its per-instance `admittedInstanceOrNull` executes `directClosureCallSelectionForPreludeOrNull` and tests the exact unobservable ReturnHome before entry. On miss the terminal operation uses the full generic fallback.
4. [`ProtosClosureCallPreparation.java` lines 343–399 and 472–525](https://github.com/guillermomolina/protos/blob/edcb758fadb0e749cd45711cd664044d0b6db6bd/src/main/java/com/guillermomolina/protos/execution/bytecode/activation/ProtosClosureCallPreparation.java#L343-L399): the **guarded first tier** uses `ProtosValueLookup.lookupGuarded(receiver, "call", prelude)` and an `Assumption`; this path already avoids repeated lookup on valid cached instance hits. The **definition tier** uses per-instance ordinary `ProtosValueLookup.lookup` without that same retained structural stability guarantee. Full generic Call1 creates `List.of(supplied0)` and calls `prepareClosureCall`.
5. [`ProtosClosureCallPreparation.java` lines 590–680](https://github.com/guillermomolina/protos/blob/edcb758fadb0e749cd45711cd664044d0b6db6bd/src/main/java/com/guillermomolina/protos/execution/bytecode/activation/ProtosClosureCallPreparation.java#L590-L680): genuine D013 `call` lookup/slot-home selection is required; only the **exact canonical selected Object.call** is intrinsics-admitted. An ordinary override remains an ordinary selected method and can prepare activation/native/structured behavior. This semantic requirement is **not** an invitation to replace lookup with unconditional `instanceof Closure`.
6. [`ProtosTailCallContinuation.java` lines 107–160, 381–455](https://github.com/guillermomolina/protos/blob/edcb758fadb0e749cd45711cd664044d0b6db6bd/src/main/java/com/guillermomolina/protos/execution/bytecode/activation/ProtosTailCallContinuation.java#L381-L455): `completeOrDefer` returns an ordinary outcome directly or creates a continuation transport **only on actual suspension**. A generic prepared terminal call has multi-branch exception/transfer/failure ownership and four prepared-call shapes (`OrdinarySourceCall`, `NativeCall`, `ImmediateResultCall`, `ModuleInitializationCall`). Whether these generic branches are actually surviving on a compiled direct hit requires graph proof; method ancestry alone is insufficient.

13. ## Specific open questions to resolve before drafting an I

1. For a new Closure object that shares canonical definition and target but may have its own mutable `call` slot, can structural lookup validity be tracked by a reusable shape/delegation proof under current Protos object storage without introducing a new global institution? If no, prove the limit and specify the smallest allowed normal-path work.
2. Does `InvokeClosureOneTail.definitionSource`'s generic preparation actually become part of the selected current-tier direct graph, or does Truffle specialize it away? Identify exact branch reachability and surviving nodes; historical method ancestry is insufficient.
3. Does the benchmark's outer `run` root follow `prologFrameAuthority`? Trace the emitted-root conditions exactly. Which specific activation/frame objects still survive compiled optimization in **both** roots?
4. Does newly constructed `ProtosClosureValue` re-read, compute or rematerialize target/plan on each call? Which entries are guaranteed stable by existing published facts and which can change when Context switches?
5. What concrete closure/activation state must be retained for mutable captured lexical contexts under D179 even when the body just returns its argument? Can it be reachable without eagerly constructing a rich context/authority?
6. What physical path does GraalPy actually take for fresh `PFunction` on its compiled workload: unary direct identity PIC vs `CallNode` -> root-keyed `FunctionCachedCallNode`? Inspect actual specialization behavior instead of assuming the first fast method fires.
7. What exact per-node IR data/control dependences distinguish correct Protos semantic overhead from redundant universal machinery? Record node groups without double counting.
8. Which exact previously ratified PLAT clauses, if any, make a demonstrated solution impossible? Do not propose amending PLAT062 solely because GraalPy uses helper classes.
