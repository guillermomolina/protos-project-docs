## Published implementation

- **Explicit authority:** The frozen source-backed Core `Entropy` behavior is not an ambient permission. Host authorization installs bootstrap-local `entropy` only for the initial RootActor. Standalone applications opt in with `--allow-entropy`; Java embedding uses `protos.AllowEntropy`, default false. Network, Resolver, Filesystem, Process access, imports and bundled Tools do not imply Entropy.
- **Future-based bytes:** `entropy.bytes(count)` returns a Future. Integer counts in `0..65536` yield exactly that many octets as fresh mutable standard `Bytes`; invalid arguments and host/provider failures use ordinary failed-Future paths. `entropy.close()` follows the revocable idempotent lifecycle.
- **Private host boundary:** A private Entropy bridge and lazily provisioned secure backend supply random bytes outside Actor turns, with bounded work, cancellation/commit handling, host custody and Process termination cleanup. No public seeded generator or cryptographic provider registry was introduced.
- **Isolation:** Live Entropy authority is nontransferable in Actor graph transfer and isolated-P capture. Completed generated Bytes remain ordinary copy-transferable data. An ActorRef broker example shows the intended child/Worker composition without passing the grant.
- **Source, tests, and documentation:** `protos/lib/core/entropy/Entropy.protos`; Java runtime/embedding/CLI implementations under `src/main/java/`; focused JUnit tests under `src/test/java/`; `protos/examples/entropy/{secure-bytes,actor-broker}.protos`; `scripts/i157-entropy-smoke.py`; updates to CLI, Process/authority and embedding guides. The Core source and CLI test were relocated into their own directories to respect the repository's 30-file direct-directory limit.
- **Normative publication:** `spec/io/ENTROPY.md`, `spec/io/IO_CORE.md`, `spec/io/PROCESS_IO.md`, concurrency cross-references, and `spec/PROTOS_SPEC_CHANGELOG.md` were included in the exact product commit.
