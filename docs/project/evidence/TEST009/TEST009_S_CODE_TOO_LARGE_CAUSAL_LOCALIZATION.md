## Upstream failure semantics

The current product uses GraalVM / Truffle `25.4.4.1.1`.

For this version, the Truffle compiler sequence is materially:

~~~text
partial evaluation / Truffle tier
  -> Graal compilation
  -> CompilationResult produced
  -> Graal-tier completion callback
  -> HotSpot/JVMCI code installation
~~~

The observed `Code installation failed: code is too large` condition happens
during HotSpot/JVMCI installation, after Graal has already generated a
`CompilationResult`.

JDK 25 JVMCI computes the required install buffer as:

~~~text
total_size =
    aligned(constants_size)
  + aligned(code_size)
  + estimated_stub_size
~~~

and returns `code_too_large` when:

~~~text
total_size > JVMCINMethodSizeLimit
~~~

The JDK 25 default limit is:

~~~text
JVMCINMethodSizeLimit=(80*K)*wordSize
~~~

Therefore the failure proves only that the final JVMCI installation footprint
crossed that limit. It does not by itself prove excessive partial evaluation,
guest call-target inlining, Java-method expansion, specialization/control-flow
explosion, or generated-root shape.

## Current Protos architecture relevant to the skew

`ProtosSemanticBytecodeRootNode` is the generated tagged interpreter for
guest-semantic top-level/module/Closure roots. Object bodies are lowered inline,
and lexically nested Closure roots share the same `BytecodeRootNodes` parse
group.

`ProtosBytecodeRootNode` is the untagged structured-dispatch/C-prime
interpreter.

The semantic interpreter delegates source-surface operation implementations to
the single implementation authority in `ProtosBytecodeRootNode`, but must
repeat Bytecode DSL operation declarations, operands, specialization guards and
caches because one generated Bytecode DSL interpreter cannot declare operations
owned by another.

Descriptive source counts at the analyzed revision are:

~~~text

  @Specialization     194
  @ConstantOperand     85

ProtosBytecodeRootNode:
  source lines       9604
  @Operation          228
  @Specialization     366
  @ConstantOperand     21
~~~

These counts are evidence about shape only. They are not a causal verdict.

TEST009-S retains the following hypothesis set:

~~~text

H6_FINAL_CODEGEN_SIZE
H7_SHARED_SYSTEMATIC_MECHANISM
H8_MULTIPLE_CAUSAL_SUBFAMILIES
~~~

The required discriminators are:

| Hypothesis | Supporting discriminator | Refuting discriminator |
| --- | --- | --- |
| H1 | failing semantic roots share generated-root/node expansion shape with no narrower dominant cause | comparable semantic roots compile successfully or another dominant mechanism explains failures |
| H2 | failing roots are already large at Truffle-tier graph completion | Truffle-tier graph is ordinary relative to successful controls |
| H3 | excess follows a repeatable guest call-target inlining tree | failures show little/no relevant guest inlining |
| H4 | one/few Java methods dominate expansion across failures | expansion is distributed and no method family dominates |
| H5 | graph growth is distributed across specializations/control-flow/node families | a narrower call/inlining/method mechanism explains the growth |
| H6 | Truffle/Graal graph sizes are ordinary but final installation still exceeds JVMCI limit | failures are already clear graph-size outliers upstream |
| H7 | all 21 semantic failures share the same causal vector | failures separate into stable distinct vectors |
| H8 | two or more stable causal subfamilies appear | all 21 share one mechanism |

No source repair is selected until this matrix is discriminated.

## Minimal causal acquisition selected for TEST009-T

The next slice must be a bounded diagnostic implementation. It must not modify
Protos language/runtime semantics or attempt the eventual compilerability
repair.

The minimal acquisition is:

1. install a diagnostic-only `OptimizedTruffleRuntimeListener`;
2. assign a run-local identity to each compiling target;
3. capture graph counts at Truffle-tier completion and Graal-tier completion;
4. capture success/failure outcome for the same run-local target;
5. preserve a durable root key independent of object addresses;
6. parse and correlate the already-enabled method-expansion, node-expansion and
   inlining traces;
7. emit one deterministic causal manifest across the complete 21-failure target
   set plus successful controls.

Required per-compilation fields:

~~~text

ROOT_NAME
~~~

~~~text

~~~

It must not invent a target-code size that the listener/API does not expose for
the failed installation.

## Correlation design

Process-local identities such as these are forbidden as durable keys:

~~~text
ProtosSemanticBytecodeRootNodeGen@3ab40a91
PiNode#...
generated node ids
lambda object addresses
~~~

They may only be used transiently inside one process to correlate callbacks.

The run-local key should therefore be:

~~~text
RUN_CORRELATION_KEY=
  target object identity
  + monotonically assigned listener sequence
~~~

The persisted cross-run identity must be derived from stable root metadata:

~~~text
DURABLE_ROOT_KEY=
  ROOT_FAMILY
  + CANONICAL_SOURCE_URI
  + EXACT_SOURCE_SECTION[start,length]
  + SEMANTIC_ROOT_KIND
  + CONTINUATION_RESUME_BCI_WHEN_APPLICABLE
~~~

If those fields are not sufficient to distinguish a root, the acquisition must
fail closed and add another stable structural field. It must never fall back to
an object address.

A JVMCI/Truffle compilation id may be stored only as a run-local field.

causal discriminator.

Therefore the intended delta is:

~~~text
ACQUISITION_CHANGES_COMPILATION_BEHAVIOR=NO
~~~

## Deterministic stop condition

The acquisition is complete when all 21 residual semantic `CodeTooLarge`
targets have:

~~~text
durable root identity
+ Truffle-tier graph size
+ Graal-tier graph size
+ inlining evidence
+ method-expansion evidence
+ node-expansion evidence
+ final outcome
~~~

and the resulting vectors prove either:

~~~text
A) one shared causal cluster
or
B) multiple stable causal subfamilies with explicit discriminators
~~~

At that point the next slice may select one structural remedy per proven causal
class.

The acquisition must not iterate by changing boundaries, graph limits, inlining
budgets or other compiler behavior between runs.
