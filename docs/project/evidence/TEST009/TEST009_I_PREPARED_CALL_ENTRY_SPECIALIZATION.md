## Product change

`EnterClosureCall` in both generated Bytecode interpreter declarations now
specializes on concrete prepared-call representations rather than receiving the
generic `PreparedClosureCall` interface.

The published representation-specific topology is:

~~~text
ImmediateResultCall
  immediate

NativeCall
  nativeCall

OrdinarySourceCall
  ordinaryDirect
  ordinaryIndirect

ModuleInitializationCall
  moduleImmediate
  moduleDirect
  moduleIndirect
~~~

The source-call specializations retain direct-target caching and indirect
fallback. Ordinary-source and module-initialization source paths now own
separate DSL specializations, so the existing direct-call cache limit of three
targets applies independently to each representation. This is an internal call
node caching distinction only; target selection and observable Protos behavior
are unchanged.

Both indirect fallbacks share the indirect call node. Existing control-transfer,
module-initialization failure and runtime-failure behavior remains owned by the
concrete prepared-call representations.

No new `@TruffleBoundary`, `@CompilationFinal`, `Assumption`, representation
flag, enum discriminator or observable language-semantic change was introduced.
