## Bounded objective

The retained post-F1 PERF025 audit identified a guest hot-path Context
acquisition pattern that discarded an available Truffle node:

```text
org.graalvm.polyglot.Context.getCurrent()
    -> ProtosLanguageContext ContextReference.get(null)
```

Direct Closure-call and send specializations already execute inside generated
Truffle Bytecode nodes, so this slice makes those guest specializations obtain
their `ProtosLanguageContext` through the current node instead:

```text
ContextReference.get(current guest Node)
```

The slice also removes repeated ambient Context rediscovery from helper chains
when the outer specialization already obtained and guarded the exact entered
Context.

No observable Protos semantic, specification, Context-policy, Process-ownership,
Task/Actor, lookup, Closure, send, or projection rule changes.

## Node-aware language Context access

`ProtosLanguageContext` now exposes the guest-node form:

```java
static ProtosLanguageContext current(Node node) {
    return REFERENCE.get(node);
}
```

The existing node-less forms remain available for host/boundary callers that do
not own an adopted guest node:

```text
current()
currentIfEnteredForRuntime()
```

The optimization therefore changes the guest acquisition institution without
forcing node-aware assumptions onto host or runtime-boundary code.

```text
NODE_AWARE_CONTEXT_REFERENCE=YES
GLOBAL_NODELESS_CONTEXT_REMOVAL=NO
HOST_BOUNDARY_COMPATIBILITY=PRESERVED
```

## Generated Bytecode hot paths

Both generated interpreters now bind the entered Context through `$node`:

```text
ProtosBytecodeRootNode
ProtosSemanticBytecodeRootNode
```

The published source contains 20 node-aware bindings across the two roots.

Affected operation families include:

- direct zero-argument Closure calls;
- direct variadic Closure calls;
- default-argument Closure calls;
- guarded Integer sends;
- guarded ordinary sends;
- definition-keyed ordinary source-backed sends; and
- guarded structured sends.

The binding shape is:

```java
@Bind("currentEnteredContext($node)")
ProtosLanguageContext enteredContext
```

with local helper resolution through:

```java
static ProtosLanguageContext currentEnteredContext(Node node) {
    return ProtosLanguageContext.current(node);
}
```

The semantic root forwards to the same node-aware shared institution rather than
reintroducing a node-less lookup.

```text
BYTECODE_ROOT_NODE_AWARE_BINDS=10
SEMANTIC_BYTECODE_ROOT_NODE_AWARE_BINDS=10
TOTAL_NODE_AWARE_HOT_BINDS=20
```

## Proven Context propagation

Two concrete rediscovery chains were removed from the targeted hot path.

### Guarded Integer specialization establishment

The hot specialization already owns `enteredContext`. Its cached helper now
receives that Context explicitly:

```text
guardedIntegerSend
    -> createGuardedIntegerSend(..., enteredContext)
```

The pre-existing node-less overload remains for non-hot callers/tests that
explicitly use that boundary.

### Context-owned Bytecode target derivation

`fastOrdinarySendTarget` no longer calls `currentEnteredContext()` to re-prove
the same Context and then calls a helper that rediscovers it again.

The targeted chain is now:

```text
guest specialization
    -> enteredContext = ContextReference.get(current node)
    -> fastOrdinarySendTarget(closure, enteredContext)
    -> taskOwnedBytecodePlan(closure, enteredContext)
```

The original single-argument `taskOwnedBytecodePlan(closure)` remains as a
boundary-compatible overload and performs ambient discovery only for callers
that have not already established an entered Context.

```text
GUARDED_INTEGER_CONTEXT_REDISCOVERY_REMOVED=YES
FAST_SEND_CONTEXT_REDISCOVERY_REMOVED=YES
TASK_PLAN_CONTEXT_PROPAGATION=YES
BOUNDARY_OVERLOADS_PRESERVED=YES
```

## Fallback and semantic boundaries

The implementation does not broaden fast-path admission.

The following remain unchanged:

- direct Closure-call canonical-selection requirements;
- source-backed versus native Closure classification;
- ordinary D013 lookup authority;
- selector-specific `Assumption` invalidation;
- Integer wrong-domain and Error-producing fallback;
- structured-send canonical-selection classification;
- generic send/call fallback;
- foreign-Context plan detection;
- source-required Context-local reprojection;
- missing-source projection failure behavior;
- Task ownership and dynamic-control attachment; and
- host/boundary `currentIfEnteredForRuntime()` callers.

The remaining node-less runtime-discovery occurrences in
`ProtosBytecodeRootNode` are deliberate boundary/compatibility paths rather
than the targeted `@Bind` guest hot-path acquisition.

