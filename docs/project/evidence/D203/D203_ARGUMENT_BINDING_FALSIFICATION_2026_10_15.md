## Approved design and non-compensating adversarial findings

**C+E selected:** missing non-rest positional parameters bind canonical PRESENT `null` unless their `name: expression` explicit default is evaluated at that binding turn; extra supplied arguments are evaluated but ignored without trailing `...rest`; no implicit count or `args`; every formal may appear before/after explicit defaults; `...rest` only final; full sequential Context semantics retained. Do not introduce a third slot operator `:=` or conflate declaration-time `:` with runtime upsert.

**F1 — A name and rest suffix cannot recover the caller's original count.** For `f: (x, y, ...rest) => Array(x,y,rest)`, `f()` and `f(null,null)` produce identical bound values: `x=null`, `y=null`, `rest=[]`. An exact-arity guard **inside that nominal body is impossible from those bindings alone**. Existing `(...args)` can count the actual vector, but changes signature style and allocates a frozen Array per invocation under observable semantics. No implicit count builtin or new signature kind was approved.

**F2 — Source-backed inherited initialization must retain a deliberate check.** [`protos/lib/core/Object.protos`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/protos/lib/core/Object.protos) defines `_coreObjectInit: () => this`, installed as standard inherited `Object.init` by [`ProtosCoreBootstrap`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/src/main/java/com/guillermomolina/protos/execution/host/embedding/ProtosCoreBootstrap.java). [`CALLABLES.md`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/spec/semantics/CALLABLES.md) requires nonempty arguments to inherited `init` to fail before construction succeeds. Naïvely deleting Closure upper-bound checks would instead allow `Thing(1,2)` on objects without custom `init`. Preserve this independent public invariant intentionally or request a separate owner choice.

**F3 — Standard control fails silently under naïve relaxation.** Standard `Object.ifNull` and `ifNotNull` are source-backed `(block)` Closures in `protos/lib/core/Object.protos`. [`VALUES_AND_COLLECTIONS.md`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/spec/semantics/VALUES_AND_COLLECTIONS.md) requires exactly one argument. [`null-aware-control.protos`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/protos/tests/conformance/control/null-aware-control.protos) tests `null.ifNull()`, `null.ifNull(1,2)`, `null.ifNotNull()`, `null.ifNotNull(1,2)`. Without standard-level checks, unselected paths can mask invalid input. `ERRORS.md` also makes standard `fail()` zero-arity exact and requires bad-arity handling *before* generic failure emission. [`fail.protos`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/protos/tests/conformance/error/fail.protos) currently asserts only generic Error for `fail(1)`; test pass alone is insufficient to prove correct failure precedence.

**F4 — Preinitialization to null is invalid.** Current [`EXECUTION_AND_CONTROL.md`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/spec/semantics/EXECUTION_AND_CONTROL.md) distinguishes a PRESENT `null` local from ABSENT local and permits ordinary lexical fallback while absent. With an enclosing `b: 99`, a Closure `f: (a: b, b: 1) => a` called with zero arguments must let the initializer for `a` observe outer `b=99`; the later formal `b` must *not* be established at entry. Conversely, after an omitted `b` parameter's own turn, a PRESENT `null` shadows outer `b`. A default's early `context.b: 7` can cause later parameter-binding duplicate-creation failure; no `:=` repair or silent overwrite.

**F5 — Caller extras still cause effects.** Calling `(x) => x` with `(produceOne(), produceTwo())` must evaluate both supplied expressions/spreads exactly once in their prior eager order, regardless of the second value being discarded. Never shorten caller evaluation or dynamic `Object.call` dispatch based on syntactic signature.

**F6 — Rest's suffix is supplied-only.** For `f: (a: 10, ...rest) => rest`, `f()` yields a fresh frozen empty Array and `f(1,2,3)` yields frozen [2,3]. Default-produced values are not inserted into it. If a caller supplies fewer than positional formals, rest still holds only genuinely extra actual positions.

**F7 — A global `:=` is not harmless syntactic sugar.** Under existing bare `=`, assignment searches lexical parents then the receiver's own slot, while bare `:` creates only in current Context. With outer `x: 10`, `f: () => { x := 20 }` is ambiguous between updating outer x and creating local x. `obj.x := (obj.x: 10)` also presents an observable pre/post-RHS destination-selection difference. The owner decided *not* to add `:=` in D203.

**F8 — Runtime performance remains empirically open.** A missing-argument presence test is already available as `arguments.length > HEADER_LENGTH + index` in [`ProtosFrameArguments`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/src/main/java/com/guillermomolina/protos/execution/bytecode/activation/ProtosFrameArguments.java). In [`ProtosSemanticBytecodeRootNode`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/src/main/java/com/guillermomolina/protos/execution/bytecode/activation/ProtosSemanticBytecodeRootNode.java), `BindUnaryFrameParameter` and `BindRequiredFrameParameter` already guard supplied-count and slot creation; changing their missing fallback to canonical null could avoid adding DSL operations, but their authoritative/materialized fallbacks remain. [`CanonicalToBytecodeLowerer`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/src/main/java/com/guillermomolina/protos/execution/bytecode/lowering/CanonicalToBytecodeLowerer.java) still uses separate `HasFrameClosureArgument` and branch logic for defaults and a trailing `CheckFrameClosureArgumentUpperBound`, with a special zero-parameter arity rejection root. Non-default generic binding currently assumes a supplied argument; a naïve null fallback may add a condition/branch even while upper checks disappear. This is a compiler design opportunity, not an observed Tier-2 result. The existing [PERF042 builder-oracle test](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/src/test/java/com/guillermomolina/protos/execution/compiler/optimizations/ProtosPerf042IdentityBuilderOracleTest.java) pins today's unary emission with a distinct upper-bound operation.

**F9 — Cross-domain precedence and integration.** [`PARALLEL_EXECUTION.md`](https://github.com/guillermomolina/protos/blob/0c617058487be96ea05b26c04df417eda6985cbe/spec/concurrency/PARALLEL_EXECUTION.md) relies on validation precedence between ordinary arity/binding and nonparallel boundary validation; the new ordinary Closure no-arity-error semantic requires carefully preserving truly independent standard/P validation contracts. The B5 ABI, dynamic `call`, host/polyglot, rich activation, DEBUG scopes and NLR/cancellation are not authorized to change.

## Cross-language architectures (comparison, not semantic authority)

The [pinned D202 upstream comparison](../../evidence/D202/D202_GRAALPY_PRELOWERING_RESEARCH_2026_10_15.md) retains exact source revisions for:
- **GraalPy:** `oracle/graalpython@a099d006438942d54c1856c2cce7b6c2839b0c85`, `RootNodeCompiler.copyArguments` emits `CopyArguments` using `BytecodeLocal[]`, `LocalRangeAccessor` and `@ExplodeLoop`; `CreateArgumentsNode` performs Python signature/default matching *before* callee. Its host header differs and Python strict binding is not Protos's chosen semantics.
- **GraalJS:** `oracle/graaljs@4327aa1f2914bac7f810406423d70ae7f8a1888b`, `AccessIndexedArgumentNode` reads supplied arguments via indexed frame access; missing JS args produce `undefined`, *not* Protos `null` or ordinary Context slots. Architectural precedent for compact reads only.
- **TruffleRuby:** `truffleruby/truffleruby@b60b0d04dd11454012d0e8a6588514410ffacdcb`, `RubyCheckArityRootNode`/ `ReadOptionalArgumentNode`; Ruby Proc/lambda semantics differ. Do not add a parallel strict/lax Closure kind.
- **Lua 5.4 / Ruby Proc / JS:** corroborate the existence of caller-count-tolerant positional invocation with missing value defaults, each using its own value semantics. **Self/Smalltalk selectors, Python lambdas, Io block activation** demonstrate alternative strict/hybrid systems; they do not dictate Protos's contract. Exact implementation source proof for these non-Truffle systems was not freshly fetched in this iteration; do not represent them as new pinned benchmark results.

**Do not sum scores to override hard incompatibilities.** C's real deficits are silent invalid calls, inability to reconstruct supplied count from nominal formals, existing strict standard behaviors and possible more binding instructions in the generic path.
