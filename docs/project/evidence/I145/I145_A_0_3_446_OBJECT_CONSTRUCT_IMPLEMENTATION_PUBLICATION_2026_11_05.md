## Published semantic and implementation results

- **Ordinary D013 call lookup retained.** Parenthesized invocation still selects `call` after evaluating arguments. Actual standard `Object.call` on an eligible non-Closure ordinary receiver sends the ordinary `construct` message and returns the exact selected result; Closure execution and custom `call` precedence are preserved.
- **One standard `Object.construct`.** The frozen root publishes a native implementation that creates a fresh child with immutable parent equal to the receiver, sends the child `init` with the original positional/named argument packet, ignores normal `init` result and returns the child. A custom `construct` may return any result without automatic `init` or forced allocation.
- **Structured execution and D237 forwarding.** The prepared standard `Object.call` path no longer allocates a child prematurely; a dedicated `OBJECT_CONSTRUCT` structured preparation executes `init` as a suspendable child call. The real selected standard executable bodies transparently forward positional/named packets through `call → construct → init`, including copying, aliasing and extraction. No second callable universe or factory registry is introduced.
- **Canonical factory/literal migration.** Source and native factory slots move from own `call` to own `construct`, including Range/InvertedRange with `super.construct`, standard collections, conversions, Byte/Text I/O, math, datetime, logging, style and the private CommandLine builder factory. The genuine executable Test descriptor `call` is retained. Map literal `%{...}` eligibility checks canonical standard `Object.call` **and** `Map.construct` before entry evaluation.
- **Actor-bootstrap consequences explicitly migrated.** `Actor.spawn(module, bindingName, ...)` selects an exact local module binding, not an inherited method. Source examples/tutorials/benchmarks, Java embedding tests and the actors guide that referred to `Actor.spawn("std:collections/Set", "call", ...)` now select the factory's local `"construct"` binding. This is a compatibility consequence of the intentional factory-slot rename, **not** a redesign of Actor bootstrap.
- **TEST009-D generated bytecode baseline** updated for the changed `StructuredPrepareChildCall`/generated bytecode topology; the committed baseline differs by one replacement entry. The final `make check` status below is maintainer-attested, not an independent rerun of individual guard stages.
