## Implementation by formal owner

### I147 — CommandLine named parameters

- [`protos/lib/cli/CommandLine.protos`](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/lib/cli/CommandLine.protos) defines the nine required named fields of `option` and five required named fields of `positional`, with private identity defaults separating omission from explicit `null`. Private `normalizeOption` / `normalizePositional` retain the original value validation and fresh frozen canonical records.
- `command(descriptor)` still consumes nested ordinary-object/Array descriptors; it uses the private normalizers directly, retains the iterative active-path cycle check and 4096-level conformance coverage, and does not expose the private helper as module surface.
- [Test Tool options](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/tools/test/Options.protos), [CLI source tests](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/tests/library/cli/), [named specification/4096-depth cases](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/tests/library/cli/specification-and-result.protos), [Java CommandLine integration](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/src/test/java/com/guillermomolina/protos/execution/integration/modules/ProtosCommandLineSpecModuleTest.java), and [new CLI guide](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/docs/guide/library/cli.md) were migrated. The old `option(descriptor)` and `positional(descriptor)` public forms are retired.

### I149 — Host and UrlClient

- [`protos/lib/http/Host.protos`](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/lib/http/Host.protos) makes `workers: 1`, `maxConnections: 64`, `maxPendingAccepts: workers`, `limits: null` ordinary public named formals of `owning` and `owningWithFactory`. The private object still goes through existing `admit` / `HostConfig.capture`; `initialization` is still its separate Actor payload and `limits` remains an ordinary policy value.
- [`protos/lib/http/internal/HostConfig.protos`](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/lib/http/internal/HostConfig.protos) now guards `positive32` comparisons with `Integer.recognizes`. [Host construction conformance](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/tests/library/http/host-construction.protos) covers non-Integer objects in all three numeric options and both public constructors; [real listener Java integration](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/src/test/java/com/guillermomolina/protos/execution/integration/http/ProtosHttpHostIntegrationTest.java) includes invalid-value rejection without listener custody.
- [`protos/lib/http/UrlClient.protos`](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/lib/http/UrlClient.protos) uses `requestOne(url, request, limits, network:, resolver:, trust:)` with three explicitly supplied capabilities and a private omission identity. Correctly bound missing authorities fail a `Future<InvalidIOArgument>`, distinct from explicit `null`. Request and limits objects remain values; the existing `UrlRequest.prepare` / session path is retained.
- [`UrlSession.protos`](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/lib/http/internal/UrlSession.protos) removes the retired trailing empty TLS options bag. [URL-client source tests](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/tests/library/http/url-client-admission.protos), [Java integration](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/src/test/java/com/guillermomolina/protos/execution/integration/http/ProtosHttpUrlClientIntegrationTest.java), [HTTP guide](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/docs/guide/library/http.md), and [HTTP normative specification](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/spec/io/HTTP.md) §§15/18 use the new forms.

### I150 — TLS Client named handshake options

- [`protos/lib/tls/Client.protos`](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/lib/tls/Client.protos): borrowed `handshake` and `handshake.owning` accept `minimumVersion: "1.2"`, `alpn: "http/1.1"`, `maxHandshakeBytes: 1048576`, `maxQueuedWriteBytes: 33554432`. A private options record still feeds existing `Options.capture`; there is no generic kwargs/native bridge or alternative public selector.
- Omitting ALPN offers HTTP/1.1; explicit `alpn: null` disables ALPN. The old final options object is retired; invalid bound values remain failed `Future<InvalidIOArgument>`; D237 invalid name/position collisions signal generic Error before callee entry.
- [TLS admission](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/tests/library/tls/client-admission.protos), [handshake tests](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/protos/tests/library/tls/client-handshake.protos), [Java TLS integration](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/src/test/java/com/guillermomolina/protos/execution/integration/tls/ProtosTlsClientIntegrationTest.java), [TLS guide](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/docs/guide/library/tls.md), and [normative TLS specification](https://github.com/guillermomolina/protos/blob/380548e10cec893581ee25ebf00da9c5c6bd7399/spec/io/TLS.md) were migrated.
