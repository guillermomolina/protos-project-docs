## Adversarial compatibility evidence

1. **D237 unknown named item** fails *before selected callee entry*, generic Error. Existing invalid object slots on future-returning I/O yield `Future<InvalidIOArgument>`, and invalid Host options synchronous `InvalidIOArgument`. This intentionally changes only invalid **call association**, not correctly associated invalid **values**. Approval explicitly includes the delta.
2. **D203 absent vs explicit null:** CLI and listenTCP require presence even for nullable values; ordinary missing non-default parameter would bind null, so use privately captured sentinel (or equivalent compliant source mechanism). TLS `alpn:null` is a meaningful explicit disable, not omission.
3. **Object-body local lookup:** source `{ x: 1; y: x }` can use an earlier object slot. `f(x:1,y:x)` evaluates `x` in caller; no safe global textual rewrite.
4. **Native boundary:** Filesystem/Network native Closure does not accept arbitrary named labels merely because guest Syntax recognizes them. Must use explicitly declared semantic signature and no hidden generic interop kwargs.
5. **Actorship:** Host listener custody, Worker creation quotas, transfer copies, TLS trust and ownership, URL authorization, filesystem/network preflight and cancellation retain old semantics.
6. **No benchmark fabrication:** Graal may virtualize input object, named binding also costs; no measured allocation or compiled-tier performance result exists.
