## 2. Verified product delta

**Single physical lowering:** `ProtosExecutionMode.java` removed; experimental `protos.Debug` option retired; profile propagation removed across language/Context, source compiler, runtime host/session, module runtime, Closure execution plans and call-preparation/projection checks. `CanonicalToBytecodeLowerer` removes the eight old NORMAL-only admission prerequisites but retains independent proof/semantic requirements. `CanonicalNonSuspensionAnalysis.Precondition.NORMAL_PROFILE` removed; one generated Bytecode root/interpreter remains.

**Passive tags without invented execution:** surviving executable source statements in the I101-B scalar-local body, constant-return roots, and the terminal of dead-prefix I095 inlining receive source-bounded `StatementTag` / `ExpressionTag` builder markup. Folded-away pure prefixes, callback roots and calls are **not** recreated. The published tests assert that DEFAULT bytecode contains no materialized tag instructions and continue to compare independently handwritten Builder oracles and physical budgets.

**Real debugger scopes:** published `ProtosBytecodeRootNode.unprojectedFrameNativeBindingsForTooling` reads PRESENT Bytecode locals with `isCleared` and `getLocalValue` at the suspended position. `ProtosBytecodeTagTreeNodeExports.getScope` overlays these existing values read-only when a previously existing activation Context prevented ordinary frame-authority projection. No extra guest activation, CallTarget, or frame is installed. A regression test exercises `first: 7; second: first; second` with a debugger attached before lowering and after a DEFAULT warm call; it checks visibility only after initialization and two actual guest frames.

**D208 normative migration:** `spec/semantics/MODULES.md` §73 and §73A and `spec/PROTOS_SPEC_CHANGELOG.md` entry `0.1.463` now specify `std:runtime.info/0` as a fresh frozen ordinary Object with exactly **four String own slots**: `implementation`, `implementationVersion`, `engineVersion`, `platform`. The `executionMode` slot is gone. Production metadata facility, `protos/lib/runtime.protos`, conformance test and public library guides align. `isDebugMode()` now means the host was opened with the actual `openDebug()` DAP facility; ordinary host remains non-DAP. `protos.Inspect` remains independent and authorization-checked.

**Static PE/accessor guard coverage:** the commit updates static fixture inventories affected by the tooling-only Bytecode access, with a Truffle boundary on those reads.
