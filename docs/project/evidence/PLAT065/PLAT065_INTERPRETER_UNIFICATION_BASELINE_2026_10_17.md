## Approved invariants and unresolved choice

The owner explicitly approved eliminating the two generated Truffle Bytecode DSL interpreters in favor of **one generated interpreter**, without permanent debug-execution overhead in NORMAL, extra runtime universes, loss of optimizations or weakened debugger correctness in DEBUG. This is a new explicit direction relative to PLAT041/#759 and PLAT042/#760. Existing ratifications remain historical and must be explicitly reconciled by GITHUB021.

PLAT058/#891 already ratified one shared Canonical-to-Bytecode lowerer with immutable per-Context NORMAL/DEBUG physical emission profiles, replay-stable compilation facts and no post-hoc DEBUG attachment guarantee for NORMAL. `BytecodeConfig` and DSL `@Instrumentation` are *different mechanisms* from this emission profile. The owner **deferred** the distinct question of separate release/debug native distributions and complete physical absence of static instrumentation support from a single dual-mode executable.

**Not selected:** how to mark genuine semantic guest activations without turning physical helper dispatch roots into spurious guest frames. In particular, selective explicit `RootTag` is a *candidate*, not ratified or demonstrated fully debugger-equivalent.

## Upstream and peer evidence (not blanket parity authority)

- [Truffle `GenerateBytecode.java`](https://github.com/oracle/graal/blob/95ce1499c8c96ab7d5a6697c5b4bf42160f3b68b/truffle/src/com.oracle.truffle.api.bytecode/src/com/oracle/truffle/api/bytecode/GenerateBytecode.java): `enableTagInstrumentation` is compile-time/generator configuration, default **false**; `enableRootTagging` applies automatically to *each* root when enabled. Manual root tagging is explicitly cautioned against because probes need to run before `@Prolog`.
- [Truffle `BytecodeConfig.java`](https://github.com/oracle/graal/blob/95ce1499c8c96ab7d5a6697c5b4bf42160f3b68b/truffle/src/com.oracle.truffle.api.bytecode/src/com/oracle/truffle/api/bytecode/BytecodeConfig.java): `DEFAULT` omits optional source/instrumentation materialization; `newConfigBuilder().addTag(...)` selects tags. [`BytecodeRootNodes.update`](https://github.com/oracle/graal/blob/95ce1499c8c96ab7d5a6697c5b4bf42160f3b68b/truffle/src/com.oracle.truffle.api.bytecode/src/com/oracle/truffle/api/bytecode/BytecodeRootNodes.java) can reparse and deoptimize when materializing tags; a `DEFAULT` root does not prove code for optional instrumentation is absent from its generated class.
- [GraalPy `PBytecodeDSLRootNode`](https://github.com/oracle/graalpython/blob/master/graalpython/com.oracle.graal.python/src/com/oracle/graal/python/nodes/bytecode_dsl/PBytecodeDSLRootNode.java): one primary `@GenerateBytecode` with `enableTagInstrumentation=true`, automatic tagging and `@Prolog` for its Python-specific lifecycle. This is a one-generator precedent, not a selective manual-root proof.
- [Oracle SimpleLanguage `SLBytecodeRootNode`](https://github.com/oracle/graal/blob/95ce1499c8c96ab7d5a6697c5b4bf42160f3b68b/truffle/src/com.oracle.truffle.sl/src/com/oracle/truffle/sl/bytecode/SLBytecodeRootNode.java): one `@GenerateBytecode`, `enableTagInstrumentation=true`, manual RootBody tagging for body/prolog placement. Not selective RootTag proof.
- [TrufflePascal `PascalBytecodeEmitter`](https://github.com/d45h71/TrufflePascal/blob/fcae9007500369dd194c7e09c932fd4807d64fa8/language/src/main/java/org/trufflepascal/bytecode/PascalBytecodeEmitter.java): explicit `beginTag(RootTag.class)` and `RootBodyTag` with automatic root tagging disabled. Its debugger-stepping qualification is incomplete; treat as mechanism precedent only.
- GraalJS uses an AST/Node instrumentation mechanism rather than Bytecode DSL. It is useful for lifecycle/observability design, **not** a compatible generated Bytecode interpreter reference.

## Required falsification matrix / next independent research

- Distinguish **always-on DEBUG infrastructure** from normal execution metadata and failure-path diagnostic requests; preserve latter with no new successful-path cost.
- Compare manual selective RootTag, automatic RootTag + supported tool filtering/topology, and one-generator supported root classification alternatives, with full before-Prolog, yield/resume, Error/unwind and debugger event ordering.
- Account for physical lexical grouping, `MaterializedLocalAccessor`, `BytecodeRootNodes` reparse, grouped roots, multi-Context isolation, root-specific interceptors, C-prime, immutable modes, optional tracing and generated code/native footprint.
- Cross-check PLAT026, PLAT041/#759, PLAT042/#760, PLAT044, PLAT058/#891, and independent PLAT064-C/D/E (#915/#916/#917). Do not rewrite historical approvals; any conflicting invariant needs an explicit GITHUB021 delta and owner acceptance.
