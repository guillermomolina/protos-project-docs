## Approved boundary and invariant reconciliation (GITHUB021)

Keep the existing UTF8, UTF16LE, UTF16BE and Latin1 conversion implementations, BOM matching and replacement/maximal-subpart policy, exact semantic descriptor recognition, trusted HostCodec provisioning, transactional per-flow encoder/decoder state, TextReader framing/byte accounting, TextWriter validation/ordering, and operation-owned C-prime and lifecycle custody. Higher-level library algorithms and policies remain Protos-first (JSON, Markdown, CSV, Base64url, IDNA and text module composition).

No public Encoding API, new scalar protocol, public Bytes binding, new Java bridge, codec registry, scheduler, hidden Task, new representation or normative change is authorized. Do not introduce redundant UTF8 transcodes merely to move source ownership. Future equivalent source migration remains admissible when existing mechanisms justify it; retention is not a permanent ban. No mandatory Java deletion, quantitative success target, benchmark campaign, new I issue or implementation slice. This preserves the earlier approved selective direction, the parent AUD025 invariants, PLAT081-A, PLAT028/029/030/070, D112/D121, exact Errors, long/double/boolean guest primitives, ordinary message semantics and specialized hot paths, isolation, snapshots, suspension, Native Image and stable Process encoding associations. Retention does not certify existing implementation correctness. Any future production Java change still requires verified exact method, annotation and behavior precedent in GraalPy or another Truffle language.

## Candidate assessment

C0 retained boundary (selected); C1 native UTF8 as intermediate to source UTF16/Latin1 (redundant conversion and no installed common streaming seam); C2 native codecs with source framing (needs transactional decoded-unit exposure and operation-owned invocation); C3 broader migration with new scalar primitives/bridges (unjustified infrastructure). Earlier whole-source and wholesale host conversion options likewise lack exact contracts. The twelve-criterion comparison considered correctness, alignment, proportionality, incremental growth, future options, scalability, simplicity, portability, resource cost, failure/operability, reversibility and evidence maturity. C0 is preferred because it avoids new crossings and preserves the existing state/commitment model; C1/C2 have plausible pure arithmetic but no demonstrated simplification; C3 crosses the no-new-infrastructure boundary. Confidence high in source boundary identification, moderate in alternative structural assessment, low in unmeasured runtime costs. Scores were qualitative decision aids, not acceptance metrics. Strongest objection: portable arithmetic remains Java-owned; revisiting is justified if independently motivated scalar/operation facilities become available. Deferral requires no public contract change.

Adversarial cases: split multibyte sequences and BOM, invalid UTF16, stateful control octets in line budgets, malformed data after CR, late cancelled reads preserving input, unrepresentable Latin1 before target effect, ordered predecessor poison including empty writes, actor termination, Context ownership and Native Image. Current tests inspected by declarations and selected bodies include ProtosStandardEncodingProtocolTest, ProtosEncodingTransferTest, ProtosTextIoFinalConformanceTest, ProtosTextReaderLineProtocolTest, ProtosStandardTextReaderProtocolTest, ProtosStandardTextWriterProtocolTest, ProtosProcessStandardStreamEncodingTest, ProtosPerf006Plat029TextReaderCallbackTest, ProtosPerf006Plat029TextWriterCallbackTest and ProtosPlat070IoCPrimeTransferAccountingTest. Guest suites under conformance/encoding, text-reader, text-writer and library/text. No tests run.

## Independent static finding — reproduction pending

ProtosTextWriter.driveWrite commits the outer operation and installs encoder preview state before target.write; driveFlush similarly commits before target.flush. Compare TEXT_IO §17 and BYTE_IO §7.1 delegated-first-effect evidence (ZERO_EFFECT, KNOWN_EFFECT, UNKNOWN_EFFECT_FAILURE). A controlled pending lower Future that can prove zero effect on cancellation may expose premature commitment. Reproduce cancellation and close races, zero-byte and state-only encoder cases, unknown-effect failure and exact error/ordering behavior before selecting a repair. Existing ProtosIoOperation first-effect arbitration is the relevant established mechanism. This is a static hypothesis, not a confirmed dynamic failure or authorized implementation change. No BUG identifier allocated; search of TextWriter commitment issues found related historical decisions but no dedicated matching defect. Do not conflate this hypothesis with the approved architecture or block the no-migration disposition.
