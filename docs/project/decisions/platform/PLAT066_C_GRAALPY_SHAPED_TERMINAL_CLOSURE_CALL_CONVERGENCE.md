# PLAT066-C — GraalPy-shaped terminal Closure invocation

**Approved:** 2026-10-18. **Owner statement:** "aprobados los cambios", followed by "D013, lo dejamos para mas adelante por si hace falta, y el resto ajustar lo que haga falta". **Product baseline:** [`guillermomolina/protos@fcc5c405413d70df546c5a9e5fa2c57b78c8ec91`](https://github.com/guillermomolina/protos/commit/fcc5c405413d70df546c5a9e5fa2c57b78c8ec91) (`0.3.380-SNAPSHOT`). **Upstream comparator:** [`oracle/graalpython@graal-25.4.4`](https://github.com/oracle/graalpython/tree/graal-25.4.4). **Decision/research owner:** [PLAT066-C/#930](https://github.com/guillermomolina/protos/issues/930); **implementation:** [I115/#931](https://github.com/guillermomolina/protos/issues/931).

## Exact selected physical objective

Make the *existing* Truffle Bytecode DSL `InvokeClosureOneTail` perform approximately the same **internal responsibility sequence** as GraalPy's unary `PFunction` dispatch: **admit and select executable target by guards plus stable Assumptions → construct positional ABI → `DirectCallNode.call` → terminal completion only when necessary**. This is functional/algorithmic convergence, not Python semantics, not an asserted percent, and not a promise about a future PE node count.

**The operation owns invocation.** Its existing terminal call + Return fusion remains under PLAT062-T. No added `@Operation`, no changes to the bodies of any other DSL operation, no hidden new Bytecode instructions, no new unavoidable guest root or second interpretation universe. Upstream Java/runtime/compiler helpers, proof producers, frame encoding and caller reference readers **may and where needed must change**, rather than putting identical work under a different method name.

**D013 expressly DEFERRED:** preserve nearest ordinary `call` selection, local shadowing, selected owner/home and mutation *after operand evaluation*. The owner declines a D013 amendment at this time. Reopen only if later exact evidence shows it is indispensable and after a further explicit decision.

**Other PLAT changes APPROVED as needed:** specifically a **PLAT060-B5+ extension for a deferred caller reference** in slot 3, when the current exact-caller materialization is avoidable. The owner expressly authorized adjustment of PLAT decisions for this objective. The extension does **not** authorize a second ABI, NORMAL/DEBUG split, headerless path, changed offsets, different guest-visible caller/context identity or eager fallback materialization. Preserve five header positions `[0..4]`, supplied offset 5, fresh per-invocation `ProtosActivation` identity, and all existing general producers/consumers. See [PLAT060 decision addendum](PLAT060_B5_UNIVERSAL_ORDINARY_CLOSURE_CALL_ABI.md).

## Required source-owner transformations

1. **Selection authority and PIC:** `ProtosValueLookup.lookupGuardedCanonicalRootCall` establishes root `Object.call` selection and supplies an `Assumption`; `ProtosStandardObjectProtocol` exposes the valid selected certificate for cache establishment instead of expanding a bool-plus-rebuild tree into every direct hit. `ProtosObjectValue` supports a cheap correct own-`call` presence predicate even with unrelated slots. Every present/absent/value-changing mutation and authority replacement must maintain dependency correctness. A new local `call` after argument evaluation must miss direct and fall to exact D013 generic; restoration may reenter direct.
2. **No unnecessary Prelude:** `ProtosClosureCallPreparation` offers admission of the already-evaluated source-backed Closure without obtaining `callerPrelude`; it keeps the generic preparation and dynamic lookup unmodified for rejected values.
3. **Executable identity:** `ProtosClosureValue`, `ProtosClosureExecutionPlanCell`, `ProtosClosureExecutionPlan` and `ProtosLanguageContext.sharedBytecodeExecutionPlans` provide stable, Context-owned executable target identity, resolved once when a PIC entry is installed. A new Closure instance may reuse code but MUST retain its own receiver/capture/ReturnHome/context. Deferred plans and foreign-Context projections remain lazy and correctly invalidated/guarded.
4. **ReturnHome admission:** derive unobservable-home eligibility from immutable captured-home plus validated frozen-plan facts, not from repeated per-call runtime reconstruction. Do not allocate a physical home on a successful provably unobservable route; observable homes still take the exact legal path. Moving computation into Closure construction with equal or larger *whole-root* cost is not success.
5. **Caller under B5+:** current `EnterRoot` does **not** universally publish Activation: its prologue materializes only when installing frame lexical authority. A direct terminal caller can pass either an already-published exact Activation or a **deferred handle to the very same current B5 argument array**, without first calling `PrepareSendArguments.exactCaller`. B5 slot 3 is extended for this lane to `ProtosActivation | deferred B5 caller reference`. Resolve lazily and publish the **same** Activation when demanded; every consumer performing a raw slot-3 cast, `compactCaller`, full-header validation, `compactTask`, provenance/prelude resolution, capture escape or error/debug/Task observation must be audited and updated with the same semantics. A handle is *not* a second guest identity or authority. No eager wrapper/allocation unless unavoidable and justified. Existing fully materialized, host, method and other B5 producers remain valid.
6. **Root proof and suspension:** `CanonicalNonSuspensionAnalysis.Subject.EFFECTIVE_ROOT` and `CanonicalCompilationFacts` propagate a correct proof for the actually selected `RootCallTarget`; do not mistake a body-only proof for complete invocation. `InvokeClosureOneTail` uses an admitted proven-non-suspending direct specialization to bypass `isSuspended`/C′ deferred transport; UNKNOWN/suspendible targets retain exact continuation, cancellation, exception handling, unwind and one-time completion.
7. **Result projection:** retain semantic numeric guest conversion where required, specialize or eliminate branches only with valid representation/consumer facts. Do not move work into `EpilogForReturn` or `MaterializeCurrentClosure` and misreport it as removed.
8. **Lowerer:** `CanonicalToBytecodeLowerer` and immutable root metadata may produce/transport these facts. Keep same exact operand evaluation order, source/CallTags, one existing `InvokeClosureOneTail`, terminal `Return`, and unchanged other DSL operation bodies.

## 2026-10-19 — Owner-selected R1 refinement: invalidatable dynamic `call` selection

**Explicit bounded approval:** in the active PLAT066-C discussion, the owner requested closure **with the immediately preceding R1 proposal**, which replaces per-hit rechecking of `call` selection by a correctly invalidatable PIC guarantee modeled on GraalRuby's `LookupMethodNode`/method-entry Assumptions. This refines item 1 above **without changing the already-approved semantics or the other items**. Full source trace, alternative PIC tiers, falsifiers and tests: [PLAT066-C R1 TruffleRuby handoff](../../work/PLAT066-C/PLAT066_C_R1_TRUFFLERUBY_INVALIDATABLE_PIC_2026_10_19.md).

**Exact scope:** the receiver-identity tier may depend on that receiver's registered local-`call` selection assumption and on canonical `Object.call` stability. The definition-keyed tier cannot pretend that one receiver's assumption applies to unrelated Closure instances: it must still distinguish a current receiver's structural `call` state using an appropriately cheap shape/discriminator or fall back to full D013 resolution. All argument effects happen before selection; root override, local creation/removal, non-Closure shadows, ReturnHome, Context/projection, execution-plan mutation, B5+, and Task/DEBUG semantics remain authoritative. A derived `localCallPresent` boolean without invalidation is not equivalent to a PIC guarantee. Keep new bookkeeping demand-driven, with no mandatory per-Closure assumption allocation and no relocation into another DSL operation.

**Nonclaims:** this is an **approved mechanism direction**, not evidence that the algorithm has been implemented or that the remaining inclusive ~125 nodes are removable. R2 (caller/B5+) and R3 (numeric result projection) remain open hypotheses for the parent [PLAT066/#924](https://github.com/guillermomolina/protos/issues/924) or separately approved future implementation/research. D013 and D207 are unchanged. GitHub GITHUB015 native-parent reconciliation for [PLAT066-C/#930](https://github.com/guillermomolina/protos/issues/930) is a *separate mandatory live closure postcondition*: a native parent is presently missing and must be verified before issue closure.
