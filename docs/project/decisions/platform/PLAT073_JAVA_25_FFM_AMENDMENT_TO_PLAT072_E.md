## Exact amended terms

1. **Java floor.** Adopt Java 25 for Protos implementation source/API/classfile (`toolchain.json: java.bytecode_release=25`; `pom.xml: maven.compiler.release=25`; JVM classfile major 69). Keep exact GraalVM Community 25.5.5.0.3 / JDK 25.0.5.0.3 / matching Graal/Truffle and non-floating DIST002 contract until an independent approved upgrade. Java 21 is no longer a supported Protos implementation/runtime floor. Preserve/test compatibility of previously compiled Java 21 external provider JARs **when** their public SPI still links on the pinned Java 25 runtime; Java 21 producer bytecode compatibility is a different claim from Java 21 running Protos.
2. **Host native calls.** Use a **private Java 25 `java.lang.foreign` FFM-only Linux bridge**, no Protos-owned JNI/C shim, inside the existing host-neutral `ProtosStandardFilesystemProtocol.Backend`. It may downcall libc functions and variadic libc `syscall(long,...)` where no wrapper exists (e.g. `openat2`); it does not eliminate the libc dependency. Specify architecture-specific syscall numbers, FFM descriptors, C integer/pointer ABI, struct offsets/alignment, stable `MethodHandle`s, `errno` capture, native memory/FD ownership and Native Image foreign-call registration. No new guest-visible FFI.
3. **Preserve PLAT072-E kernel architecture in its entirety.** Descriptor-pinned exact root (no pathname/mountinfo TOCTOU), real `openat2` with `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS | RESOLVE_NO_XDEV`, grant-specific Landlock policy with sufficient handled rights including `REFER` and `TRUNCATE`, dedicated appropriately confined I/O workers, atomically safe `renameat2`/`unlinkat`, no-follow final entry semantics, complete operation/cancellation/resource/lifetime rules, no unconfined fallback.
4. **Preserve all D248-B/Protos observable authority:** single explicit `--allow-filesystem=<directory>` CLI grant, bootstrap-local RootActor Filesystem, Process/Context revocation and service lifetime, Actor/Tool/Network/Resolver isolation, embedding `Truffle FileSystem` authority and File/entries stable identity. Normative [`FILESYSTEM.md` §§18/20](https://github.com/guillermomolina/protos/blob/bfb276f9b76c663d3ef1fb68823e13a22ede136c/spec/io/FILESYSTEM.md) and [`PROCESS_IO.md` §§22/28](https://github.com/guillermomolina/protos/blob/bfb276f9b76c663d3ef1fb68823e13a22ede136c/spec/io/PROCESS_IO.md) are unchanged.
5. **Deployment.** Native feasibility requires *real supported JVM and rebuilt installed Native executable*, not a JDK API existence claim. Current published Native target is Linux x86_64, dynamic glibc >=2.39. Linux AArch64 may be added only with independent ABI/Native/security proof; macOS, Windows, musl, static execution and unsupported kernels must not receive an unproven grant. PLAT045 Native guest interpreter-only fallback remains unchanged.

## Mandatory proof and hard stop

Run **all original PLAT072 T01–T16** checks. T04/T05 must deterministically test a previously opened parent FD moved outside the authorized root before `unlinkat` or cross-directory `renameat2`. FFM and JNI are both merely call transports, **not an isolation proof**. Any outside-root effect invalidates the ratified confinement mechanism and requires a **separate owner-approved** kernel/broker containment decision, not pathname checks or an ABI swap. Missing required kernel/LSM/provider/Native capabilities must fail closed **before guest execution**.

FFM-only is conditional on proving the real Linux syscall ABI, Landlock, `errno`, `Linker.Option.firstVariadicArg` for variadic `syscall`, downcall metadata, access flags and libc linking in JVM **and** Native Image. If FFM viability fails, **do not silently switch to JNI or a hybrid**: reopen a bounded decision, with Java 25 + JNI as the conservative candidate. Do not treat existing green `make test`/`make check` as proof of not-yet-built code.

## Ownership and boundary

**DIST022** migrates the build/toolchain/CI/SPI fixtures and portable/Native distribution contract, maintaining the pinned selected JDK. **I156** implements actual Linux FFM syscalls, threads and kernel security under the unchanged backend; its FFM-dependent code waits for the Java 25 floor from DIST022. I155 remains open for full D248-B acceptance. No Multi-Release JAR, Java 22 intermediate version, general FFI, new guest APIs, extra rights, or generic sandbox architecture is selected.

This record supersedes **only** the historical PLAT072-E **Java 21 + JNI/C** bridge choice. The historic decision document is deliberately not edited; this is the versioned amendment and enduring GITHUB021 provenance.
