## Decision

D181 selects **Candidate D — producer-side exact-revision D064 publication** and
refines it with one explicit owner-approved construction invariant:

> D064 is not a website-built byproduct and is not generated by creating a
> public release. It is one member of the Protos exact-revision artifact set,
> built by the same canonical distribution-artifact construction path that
> produces the JVM and Native artifacts.

Conceptually:

~~~text
Protos revision X
    |
    | one canonical reproducible artifact-build command / entry point
    v
artifact set for X
    |-- JVM artifact(s)
    |-- Native Image artifact(s)
    |-- D064 documentation JSON
    |-- coverage/report output where applicable
    `-- manifest/checksums/provenance binding the set to X
    |
    | durable exact-revision/content-addressed publication
    v
downstream consumers

public release publication
    = separate later operation
    = may select/reuse an already validated artifact set
    = never implied by a successful artifact build
~~~

The canonical artifact-build operation must be repeatable for an exact source
revision without requiring a Git tag or GitHub Release.

A successful development/SNAPSHOT build does not create a public release.

## Ownership boundary

After D181:

~~~text
guillermomolina/protos owns:
  source interpretation
  D064 producer implementation
  producer execution
  exact-revision artifact construction
  D064 artifact identity/provenance
  producer-side D064 publication

guillermomolina/protos-website owns:
  exact source revision selection
  D064(X) acquisition
  D064 provenance/schema validation
  static Node/Astro rendering
~~~

The website therefore has no architectural requirement to:

~~~text
compile Protos
run Maven for the D064 producer
carry a JDK for the D064 producer
know the Java extractor class
know target/classes
know Protos producer classpath mechanics
~~~

The target end state is a Node-only website build with respect to D064
production.

## Reproducibility and failure contract

The selected architecture requires a canonical repository-owned construction
entry point for revision `X`.

For D064 specifically:

~~~text
same exact source/producers semantics X
    -> same deterministic D064 bytes
    -> same D064 content hash
~~~

The implementation must preserve the existing deterministic D064 serializer
contract.

For the complete artifact set, every artifact must be bound to the same exact
source authority `X`. Native Image byte-for-byte reproducibility across
different host/platform/toolchain identities is not assumed by this decision;
where host/toolchain identity is relevant it must be explicit in the artifact
identity/manifest.

The build must fail closed:

~~~text
STALE_ARTIFACT_FROM_Y_WHEN_BUILDING_X=FORBIDDEN
MIXED_X_Y_ARTIFACT_SET=FORBIDDEN
PARTIAL_SET_PRESENTED_AS_COMPLETE=FORBIDDEN
MOVING_MAIN_AS_ARTIFACT_AUTHORITY=FORBIDDEN
~~~

A manifest/checksum/provenance envelope must make the exact-revision binding of
the produced set auditable.

## Construction is not release publication

D181 explicitly preserves the release policy in
`guillermomolina/protos:AGENTS.work/RELEASE.md`.

~~~text
BUILD_ARTIFACT_SET(X)
    !=
CREATE_PUBLIC_RELEASE(X)
~~~

A `-SNAPSHOT` revision is a development trace point. It may have exact-revision
artifacts without becoming a tag, release, compatibility promise, or milestone.

A later explicitly selected public release may consume the exact validated
artifacts produced by the canonical construction path rather than beginning a
different artifact-construction architecture.

D181 does not select release cadence, version, tag, prerelease status, or release
candidate.

## Publication identity

The durable consumer contract is conceptual rather than tied here to one
registry implementation:

~~~text
source authority = exact Protos revision X
artifact authority = D064 content bound to X
consumer check = internal D064 provenance revision == X
transport integrity = content digest / equivalent immutable identity
~~~

Ordinary short-retention workflow artifacts are insufficient as the sole durable
consumer publication channel.

D181 does not require a particular transport product by name. If DIST010
implementation discovers that selecting a concrete publication/retention backend
would itself establish a materially new durable architecture beyond the contract
above, it must stop and route that exact choice through the design gate.
