## Ratified external implementation facts, so I115 implementer never needs to browse

**TruffleRuby** (`truffleruby/truffleruby@b60b0d04dd11454012d0e8a6588514410ffacdcb`): `RubyCallNode.execute` evaluates receiver and arguments before `doCall`; `DispatchNode.dispatch` resolves method; `LookupMethodNode.lookupMethodCached` guards cached lookup with `methodLookupResult.getAssumptions()`; `ModuleOperations.lookupMethodCached` registers ancestors including *absent* methods; `ModuleFields` invalidates on mutation. `SingletonClassNode` changes per-instance meta-class, so a receiver-local certificate is not a proof for unrelated receivers. `CallInternalMethodNode.callCached` invokes `DirectCallNode` under selected-method Assumptions. Protos is **not** Ruby's class system; model physical invalidation only.

**GraalPy** (`oracle/graalpython@graal-25.4.4`): `CallUnaryMethodNode.callPFunction` has guards `isSingleContext(), hasSimpleSignature(cachedFunc,1), func==cachedFunc`, assumption `cachedFunc.getCodeStableAssumption()`, constructs `PArguments.create(1)`/sets arg 0, and calls `FunctionDirectInvokeNode`. `CallDispatchers.FunctionCachedInvokeNode.callFunctionCached` guards `isSingleContext(), callee==cachedCallee` and code-stability assumption; `callFunctionCachedCt` (multi-Context) uses `callee.getCode().getRootNode()==rootNode` to share code without caching individual cross-Context function objects; megamorphic fallback is indirect. `FunctionDirectInvokeNode.doDirect` writes globals/function object into args then calls `SimpleDirectInvokeNode.doDirect`. That uses `ExecutionContext.CallContext.prepareCall(frame,args,target)` when caller frame exists, otherwise a thread-state route, before `DirectCallNode.call`. **GraalPy also prepares caller provenance conditionally; Protos must not drop it blindly.** Protos already packs 5 header slots (+ one arg); GraalPy `PArguments` has its own different header and is NOT justification for changing B5 layout. Numeric result may be returned directly on GraalPy's path; Protos guest numeric projection must remain correct even if physically moved/removed.

**Protos exact relevant source at baseline:** `ProtosObjectValue.trackSlotSelectionDependency` rejects subclass receivers despite Closure being final subclass; `createLocalSlot/removeLocalSlot` invalidate dependencies *after* storage mutation and must be audited for compile invalidation ordering. `ProtosMapBackedLexicalBindingAuthority.localCallPresent` is only a derived presence bit, not an Assumption. `ProtosClosureValue.returnHome` is final; `executionPlan` may be initially null and rematerialized once; `contextLocalExecutionProjectionRequired` can change. `ProtosClosureCallPreparation.establishDirectClosureExecutableFactsOrNull` already builds a reusable target/Context record, but older source contains profile tests that are conceptually irrelevant under this ONE-mode plan. `InvokeClosureOneTail.guardedSource` currently calls `admittedCachedInstance` on hits; `definitionSource` keys on definition/template/Context/projection; `enterDirectProven` normalizes with `guestValue`. `ProtosFrameArguments.compactDirectClosureCallOneNoHome(closure,Object,Object)` validates caller ref and stores `[closure,DIRECT_CLOSURE_CALL,null,callerRef,unobservableAcceptingPrimitiveResult,arg0]`. `CanonicalToBytecodeLowerer` terminal-call branch emits tail op then `Return` but does NOT set `epilogProjectsReturnCarrier` there.
