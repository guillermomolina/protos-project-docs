> ### 5. Primary external technical conclusions — supplied; do NOT visit the web
>
> - **RFC 8446** TLS 1.3: authenticated handshake/record layer, TLS alerts and `close_notify`; early data/PSK resumption raise replay/freshness questions, disabled here.
> - **RFC 9325** secure deployment: prefer 1.3 but allow hardened TLS 1.2; reject legacy insecure versions/suites. **RFC 5246/5746** describe TLS 1.2 and secure renegotiation bounds.
> - **RFC 9525** service identity: SAN DNS-ID/iPAddress reference matching, no CN fallback; constrain full leftmost-label wildcard to one label; Protos additionally insists on caller-supplied ASCII IDNA2008 A-label and explicit `IpAddress`.
> - **RFC 5280** PKIX chains and CA eligibility, BasicConstraints and KeyUsage constraints. **RFC 7301** ALPN: one application protocol or none, never parse unoffered HTTP/2 as HTTP/1.1.
> - **OpenJDK JSSE `SSLEngine`** (Java 25 official): nonblocking `wrap`/`unwrap` statuses `OK`, `BUFFER_UNDERFLOW`, `BUFFER_OVERFLOW`, `CLOSED`; handshake `NEED_WRAP`, `NEED_UNWRAP`, `NEED_TASK`, `FINISHED`, `NOT_HANDSHAKING`. Execute delegated tasks, drain outbound, replenish inbound and do not block on socket I/O. `X509ExtendedTrustManager`/PKIX handles chain trust; JSSE's optional built-in `HTTPS` hostname matching is **not** the strict S12 Protos identity authority. No `SSLContext.getDefault()`.
> - **GraalVM Native Image**: JCA/provider reachability needs build proof; Java `cacerts` and the effective `blacklisted.certs` state may be captured during image construction, so a native binary is **not** a live OS policy verifier. The October 2026 CA freshness advisory is a provenance warning, not a test result. Native proof is deferred to C.
> - **Truffle parallels:** **GraalJS** maintains JavaScript/Node-facing APIs over host runtime capabilities and Context/Realm state; Node TLS event-loop configuration is *not* Protos's public API. **GraalPy** exposes Python `ssl` policy at Python language level while host/native crypto interop is private, avoiding ambient policy as portable semantics. **TruffleRuby** keeps Ruby OpenSSL integration/primitive bridge behind Ruby-visible objects, not a universal multi-engine registry. **Espresso** hosts Java bytecode and can reach Java `SSLEngine`/JSSE when supported, but that availability does not define Protos Trust or certificate-name policy. **Sulong/LLVM** executes native libraries; it is an FFI substrate, *not* a certificate/trust policy contract. **Actionable rule across all five:** language-level semantics in Protos, minimal lazy context/Actor-scoped host bridge, no mutable TLS engine or certificate-authority default shared between Truffle Contexts; do not import their public API structures.
> - **Other async models:** Rust `tokio-rustls` layers TLS over an AsyncRead/AsyncWrite transport with explicit security config; Go `crypto/tls` composes `Conn` and verification but host root sources are environment-specific; .NET `SslStream` authenticates an existing stream; Python `asyncio.start_tls` upgrades an existing async stream; Node `tls.TLSSocket` is event-loop integrated. These are supporting composition precedents, not sources of Protos defaults or permission to move the public policy to Java.
