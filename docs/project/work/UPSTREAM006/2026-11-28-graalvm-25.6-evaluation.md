## Findings and disposition

The exact release retains automatic splitting during root compilation preparation. Protos uses generated Bytecode DSL root cloning and visitation; no handwritten cloning infrastructure was added. Generated source inspection established the root and continuation cloning contracts, not actual automatic-splitting coverage in isolation. GraalPy retains frame-based bytecode-index storage and existing proxy/direct-call forms; no speculative migration to new explicit-index or proxy metadata APIs was performed.

Nullable cache default annotations were simplified following equivalent upstream nullable property-getter usage. Explicit node binding was retained to satisfy the existing static PE guard. No new Java runtime machinery was introduced. The new DSL APIs (including raw-bit constants, finally serialization, explicit BCI modes and newer call forms) were not independently exhaustively exercised as feature-specific tests; no new API adoption or semantic change is claimed.

Native guest Tier-2 JIT, FFM, BCI compilerability and integrated compatibility checks passed, as recorded in [DIST028 adoption evidence](../../evidence/DIST028/2026-11-28-graalvm-25.6-adoption.md). Local exhaustive and Native tests passed; remote CI passed on its second attempt. No causal link to the independent BUG044 is asserted. The transient CI timeout exposed existing test-suite cost, tracked independently as PERF048 #1227.

The maintainer explicitly excluded comparative performance measurements, graphs and benchmarks from this adoption. They remain unperformed, with no claimed performance equivalence or measured benefit. Compatibility evaluation supports the bounded adoption; future optional upstream API or performance investigations require their own scope. No public release was authorized.
