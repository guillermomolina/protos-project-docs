> ### Relevant outside primary facts (provided inline; DO NOT browse)
>
> - **RFC 9325**: modern deployment retains TLS1.2 and TLS1.3, strongly prefers 1.3 and forbids 1.0/1.1; that is why S12 is not 1.3-only.
> - **RFC 9525**: compare the application-supplied DNS-ID/IP-ID against subjectAltName; do not use CN fallback; wildcard can only match one leftmost DNS label. Protos additionally requires pre-converted ASCII IDNA2008 A-label, no numeric IP String and explicit recognized `IpAddress`.
> - **RFC 7301**: ALPN negotiates one application protocol or none; advertise `http/1.1` only, and do not pretend another negotiated protocol can be parsed by HTTP/1.1 Client.
> - **RFC 8446**: TLS1.3 authenticates records, uses `close_notify`; TCP EOF without TLS close can indicate truncation; 0-RTT and PSK resumption have replay and freshness consequences and are disabled in S12.
> - **OpenJDK JSSE `SSLEngine`**: transport-independent nonblocking `wrap()` and `unwrap()` return `SSLEngineResult.Status` (`OK`, `BUFFER_UNDERFLOW`, `BUFFER_OVERFLOW`, `CLOSED`) and `HandshakeStatus` (`NEED_WRAP`, `NEED_UNWRAP`, `NEED_TASK`, `FINISHED`, `NOT_HANDSHAKING`). Run delegated tasks where required; do not block a Truffle Actor thread on socket I/O; handle fragmentation, byte/packet buffer bounds, application-data and close transitions. `SSLParameters` protocols/ciphers/application protocols/SNI may be configured, but Java default endpoint-verification settings **alone** do not prove the stricter Protos RFC9525 contract. Use explicit trust material and `X509ExtendedTrustManager`/PKIX verification; no `SSLContext.getDefault()` policy shortcut.
> - **GraalVM Native Image**: cryptographic provider reachability and JCA Security Services require explicit audit; default Java TrustStore and `blacklisted.certs` may be captured **at image build time**. Distinguish explicit packaged `javaCacerts()` from a live OS verifier and track CA provenance in JVM/native tests. October 2026 GraalVM CA warning is a freshness motivation, **not** a license to assert an unverified CVE result. No speculative Linux/Windows/macOS/BSD native code.
> - **Relevant Truffle parallels, already evaluated:** GraalJS/Node TLS is context/host-driven; GraalPy exposes Python `ssl` through its runtime; TruffleRuby routes Ruby/OpenSSL through host-native primitive boundaries; Espresso can execute Java/JSSE hosting; Sulong/LLVM is a low-level native substrate, **not an independent TLS semantics/API provider**. Their shared lesson is to keep language security semantics in Protos and a lazy private per-Actor host facility for the irreducible TLS/PKIX primitive. Do not import a JS/Python/Ruby/OpenSSL public API, expose a provider registry, or share mutable TLS engines across Truffle Contexts.
> - **Comparable non-Truffle models:** Rust `tokio-rustls` wraps an async duplex with explicit TLS configuration; Go `crypto/tls` composes TLS Conn with the caller's networking, but its root loading is environment-specific; .NET `SslStream` authenticates an existing stream; Python `asyncio.start_tls` upgrades an existing async transport; Node `tls.TLSSocket` integrates with its event loop. All emphasize explicit transport+identity+trust separation, not public host-specific types.
