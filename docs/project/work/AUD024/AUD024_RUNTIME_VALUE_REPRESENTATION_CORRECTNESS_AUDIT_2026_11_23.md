**Fecha de investigación:** 2026-11-23

**Identificador:** AUD024; sustituye en la misma issue el alcance histórico de PERF047 (número PERF047 consumido, no reutilizable).
**Producto inspeccionado:** [`guillermomolina/protos@89028494587d4d22309a5c048e37da3518170b18`](https://github.com/guillermomolina/protos/commit/89028494587d4d22309a5c048e37da3518170b18).

**Método:** revisión estática de código fuente y contratos normativos; contraste con métodos/anotaciones reales de GraalPy, TruffleRuby, GraalJS y FastR; búsqueda de casos contrarios y pruebas existentes. **No se ejecutaron tests, programas, builds ni benchmarks. Ningún fichero de producto ha sido modificado por esta auditoría.** El presente texto es el registro durable de investigación publicado en `guillermomolina/protos-project-docs` con autorización explícita del propietario; su publicación **no ratifica** las extensiones arquitectónicas pendientes.

## 1. Objeto y criterio de aceptación

La pregunta no es «¿qué implementación es más rápida?», sino «¿las representaciones internas de todos los tipos relevantes son **arquitectónicamente coherentes** con el dominio semántico de Protos, y están construidas y defendidas mediante mecanismos maduros de Truffle?». No se exige medición de latencia, GC, throughput o ganancia para identificar y corregir una representación inadecuada. A la inversa, el uso de `Object[]` **no es un defecto por sí solo** cuando el elemento semántico es cualquier objeto o cuando se necesita un respaldo general.

Se separan cuatro juicios: (1) **conformidad semántica observable** — gobernada por `spec/`; (2) **integridad de representación** — ningún estado interno imposible o no admitido; (3) **coherencia arquitectónica** — especializaciones primitivas correctas, transiciones y respaldo genérico; (4) **disciplina del límite** — propiedad de la memoria, copia/snapshot, interop, Actor/P y origen/resultado. No se presenta un problema del punto 3 como incumplimiento observable del punto 1 sin una demostración concreta.

El propietario fijó los objetivos de auditoría: **`Bytes` respaldado por `byte[]`**, y `Array`, `Vector` y `Matrix` con **las mismas especializaciones aplicables a sus dominios numéricos**. Ello significa `long[]` / `double[]` / respaldo `Object[]` en los tres cuando caben sus elementos; `Array` mantiene además `boolean[]`, pues a diferencia de Vector y Matrix puede contener Boolean. La auditoría **no inventa** un nuevo tipo visible `Byte`, `dtype`, un tipo Boolean en Vector/Matrix, una API FFI ni una jerarquía pública de colecciones.

Normas consultadas: [`AGENTS.md`](https://github.com/guillermomolina/protos/blob/main/AGENTS.md), `AGENTS.work/{AUDIT,DESIGN,REFERENCE,COORDINATION}.md`, `src/AGENTS.md`, `spec/AGENTS.md`, `protos/AGENTS.md`; [`VALUES_AND_COLLECTIONS.md`](https://github.com/guillermomolina/protos/blob/main/spec/semantics/VALUES_AND_COLLECTIONS.md) (§§21, Array, Vector/Matrix, modelo numérico, String, Bytes, Map e interop), `OBJECT_MODEL.md`, `BYTE_IO.md`, `TEXT_IO.md`, `FFI.md`, `ACTORS.md` §16, `PARALLEL_EXECUTION.md` §71, `ABSTRACT_RUNTIME.md`. Se contrastaron las ratificaciones previas `PLAT056`, `PLAT068`, `D214`, `D252`, `AUD009-B7/B9`, `AUD023`, `PERF011` y el límite aún abierto de `D261`.

## 3. Hallazgo AUD024-F1 — Bytes almacena una lista de objetos y su constructor host admite estados imposibles

**Fuente:** [`ProtosBytesValue.java`](https://github.com/guillermomolina/protos/blob/89028494587d4d22309a5c048e37da3518170b18/src/main/java/com/guillermomolina/protos/runtime/io/ProtosBytesValue.java). `indexedAdd(Object)` y `indexedPut(int,Object)` rechazan `null` pero no verifican por sí mismos `Integer 0..255`; el protocolo público [`ProtosStandardBytesProtocol.java`](https://github.com/guillermomolina/protos/blob/main/src/main/java/com/guillermomolina/protos/execution/protocols/io/ProtosStandardBytesProtocol.java) sí llama `requireOctet`. Por tanto, **un caller Java puede dejar un Bytes con un contenido imposible**. Eso no demuestra que un programa Protos normal lo pueda producir: es un defecto de **integridad del límite interno**, distinto del desacuerdo arquitectónico `List<Object>` frente a `byte[]`.

**Test revelador:** `src/test/java/com/guillermomolina/protos/runtime/values/ProtosAdditionalIndexedInteropTest.java`, método `bytesHostOnlyElementFailsClosed`, usa `bytes.indexedAdd(new Object())` para construir tal estado y comprueba que interop lo rechaza. La prueba defiende una prohibición de filtración, pero conserva el defecto de permitir crear el estado anómalo. Reconciliar prueba y frontera: comprobar que una escritura host inválida **falla antes de modificar** un `Bytes`; comprobar que un Bytes válido proyectado por `InteropLibrary` expone únicamente Integers sin signo y sigue siendo de solo lectura. No debilitar la prohibición de divulgar valores host.

**Arquitectura correctiva concreta:** permanecer en una sola clase Java `ProtosBytesValue`, con `private byte[]` y `int size` (longitud lógica) y capacidad privada, constructor vacío independiente y una ruta de construcción desde bloque con copia/adopción solo cuando la exclusividad sea probada. Los selectores públicos `size`, `at`, `atPut`, `add`, `removeAt`, `each` permanecen **comportamientos ordinarios en el mismo objeto Protos** y no se convierten en un API de `byte[]` host. La carga física Java usa byte firmado de ocho bits; cualquier observación entrega el valor numérico sin signo `0..255` a través de `ProtosNumericValueSupport.octet(byte & 0xff)`; esa función ya utiliza 256 valores `Long` cacheados y por tanto no hay que afirmar una asignación de Java Long nuevo por octeto. La copia `octetSnapshot()` es independiente de futuras mutaciones; `each` captura snapshot lógico al comienzo, sin pérdida de interrupción, suspensión o de la condición de retorno del receptor. `add/atPut` siguen devolviendo el objeto **exactamente suministrado** por el mensaje huésped; la representación de un octeto posteriormente leído solo necesita cumplir identidad semántica por valor, no identidad de referencia de Java.

**Casos de falsación:** vacíos y byte 0/127/128/255, índice fuera de rango, Float `1.0` rechazado aunque matemáticamente integral, BigInteger positivo 256 rechazado, receptor frozen/closed (frozen falla primero donde normativo), memoria no compartida tras dos lecturas, `each` modifica `Bytes` mientras recorre snapshot, `removeAt` corrige desplazamiento, mutación de `byte[]` reutilizado por backend no cambia un Bytes publicado, alias y ciclos del **objeto** sobreviven a la transferencia, snapshot de largo 0.

**GraalPy exacto:** [`ByteSequenceStorage.java`](https://github.com/oracle/graalpython/blob/main/graalpython/com.oracle.graal.python/src/com/oracle/graal/python/runtime/sequence/storage/ByteSequenceStorage.java) con `byte[] values`, `getIntItemNormalized` (unsigned), `ensureCapacity`, `insertByteItem`, `getCopyOfInternalArrayObject` (`Arrays.copyOf`), `@ExportLibrary(PythonBufferAccessLibrary.class)` y exportes `readByte/writeByte`. [`PByteArray.java`](https://github.com/oracle/graalpython/blob/main/graalpython/com.oracle.graal.python/src/com/oracle/graal/python/builtins/objects/bytes/PByteArray.java) delega en almacenamiento byte especializado. **No** copiar reglas de `memoryview` o redimensionamiento de Python que no pertenezcan a Protos.

## 4. Hallazgo AUD024-F2 — especialización coherente en Array, Vector y Matrix

### Qué está bien en Array

[`ProtosArrayValue.java`](https://github.com/guillermomolina/protos/blob/main/src/main/java/com/guillermomolina/protos/runtime/values/ProtosArrayValue.java) ya clasifica valores homogéneos `Long`, `Double`, `Boolean`, almacena en `long[]/double[]/boolean[]`, mantiene `Object[]` para los demás, y asciende a `Object[]` si una escritura no cabe en la representación activa. `IndexedGeneration.publishSnapshot`, `publishIndexedSnapshot` y `detachedCopy` construyen snapshots protegidos contra mutación posterior. Debe conservarse y emplearse como antecedente interno; no es correcto afirmar que Array solo usa `double[]`.

### Qué falta en Vector

[`ProtosVectorValue.java`](https://github.com/guillermomolina/protos/blob/main/src/main/java/com/guillermomolina/protos/runtime/values/ProtosVectorValue.java) tiene `private final Object[] elements`, independientemente de los Number suministrados. Una instancia que contiene exclusivamente SmallInteger o exclusivamente Float carece de sus representaciones `long[]` y `double[]` frente a `Array`. Incorporarlas exigiría que `indexedSize`, `indexedAt`, `indexedPut`, `indexedSnapshot`, `transferShellForRuntime` y `transferPutForRuntime` admitan el tipo de backing y su transición sin cambiar la identidad ni la semántica. **No introducir `boolean[]`**: el contrato de `Vector` rechaza Boolean. **No convertir BigInteger, Fraction ni Complex a double** y nunca admitir un Long que represente un Integer fuera de signed64.

### Qué falta en Matrix y dónde está el impacto oculto

[`ProtosMatrixValue.java`](https://github.com/guillermomolina/protos/blob/main/src/main/java/com/guillermomolina/protos/runtime/values/ProtosMatrixValue.java) está ratificado con R1 `Object[]` y R2 Float `double[]`. La ampliación a `long[]` **no** es simplemente añadir una rama en constructor: `indexedAt`, `indexedPut`, `indexedSnapshot`, `physicalLength`, construcción de shells de transferencia, packing, nacimiento de resultados y `ProtosStandardLinearAlgebraProtocol` contienen supuestos específicos de solo dos backings. En particular `readonlyPackedFloatsForRuntime()` hace `Object[] references = (Object[]) current` después de descartar `double[]`: fallaría al introducir `long[]` si no se reconcilia, y el resultado del CAS se convierte a `double[]` bajo hipótesis del modelo actual. **Fallo potencial demostrado del plan ingenuo de ampliación**, no un fallo actual de ejecución. Existen contratos de reducción D214-F1 que prohíben FMA y reordenamiento al tocar kernels Float.

### Regla arquitectónica propuesta (pendiente de extensión PLAT068)

La **política conceptual** del almacenamiento debe ser coherente, **sin exigir una superclase Java o un nuevo motor genérico**:

| Contenido semántico / familia | Array | Vector | Matrix |
|---|---|---|---|
| Todo SmallInteger firmado de 64 bits | `long[]` | `long[]` propuesto | `long[]` propuesto |
| Todo Float binario64 | `double[]` | `double[]` propuesto | `double[]` R2 ya presente |
| Todo Boolean | `boolean[]` | inválido | inválido |
| BigInteger, Fraction, Complex o mezcla heterogénea | `Object[]` | `Object[]` | `Object[]` |
| Vacío | representación privada elegible sin dtype observable | igual | igual; conservar filas/columnas exactas |

`atPut` debe poder pasar desde primitivo a genérico si el valor permitido ya no cabe, sin convertir o cambiar tipos, y retornar el **objeto suministrado**. Los índices, el estado frozen y la admisión se validan en el orden normativo. Copia/snapshot deben seguir independientes después de mutación y de transferencia. La especialización no convierte Array, Vector o Matrix en la **misma familia semántica**; significa aplicar el mismo criterio físico a dominios distintos.

**Conflicto de autoridad:** [`PLAT068_R2_FLOAT_ADAPTIVE_MATRIX.md`](https://github.com/guillermomolina/protos-project-docs/blob/main/docs/project/decisions/platform/PLAT068_R2_FLOAT_ADAPTIVE_MATRIX.md) dice expresamente que su aprobación **solo cubre Matrix R2-Float** y no ratifica Vector R2 ni Integer `long[]`. El propietario ha fijado ahora su deseo de armonizar las especializaciones, pero la auditoría **no puede publicar la extensión como ya ratificada**. Tras esta auditoría corresponde presentar/seleccionar un delta concreto de PLAT068 o una decisión PLAT nueva, incluyendo actualización y compatibilidad del modelo de dos estados. La decisión normativa de D214 permite representaciones primitivas invisibles; no hace falta cambiar el lenguaje público para lograrlo.

**Referencia exacta:** GraalPy [`PList`](https://github.com/oracle/graalpython/blob/main/graalpython/com.oracle.graal.python/src/com/oracle/graal/python/builtins/objects/list/PList.java) utiliza `SequenceStorageNodes.SetItemScalarGeneralizingNode` y `AppendNode`, sustituyendo almacenamiento al generalizar. Las clases `LongSequenceStorage`, `DoubleSequenceStorage` y `ObjectSequenceStorage` tienen métodos `getCopyOfInternalArrayObject`, acceso y capacidad tipados. TruffleRuby ofrece la alternativa de `@GenerateLibrary ArrayStoreLibrary`, `@ExportLibrary(receiverType=long[].class)` / `double[].class` / `Object[].class`, con `acceptsValue`, `acceptsAllValues`, `copyContents` y `boxedCopyOfRange`, pero **no justifica replicar sus múltiples clases Java** en Protos. GraalJS `AbstractIntArray` y `AbstractDoubleArray` hacen `convertToObject` cuando la representación primitiva no encaja; no transferir su modelo de holes/arrays dispersos al Array denso de Protos. FastR `RDoubleArrayVectorData` da antecedente de datos tipados con `@ExportLibrary(VectorDataLibrary.class)`, acceso y copia explícitos, pero el sistema de tipos de R difiere.

## 5. Hallazgo AUD024-F3 — String, Map, IdentityMap y estructuras que NO deben «corregirse» por parecer genéricas

**String:** `ProtosStringValue` valida UTF-16 y almacena texto host Unicode en `String`; `scalarAtForRuntime` cuenta puntos de código y no retorna mitades sustitutas. En GraalPy `PString` materializa `TruffleString` y utiliza `TruffleString.CodePointAtIndexUTF32Node` (`@Cached` en `@ExportMessage`). Es un precedente sólido para una **investigación de integración de TruffleString**, especialmente bajo acceso Unicode indexado, pero **no se halló una violación observable actual demostrada**. Migrarlo automáticamente por usar Java String sería repetir el error de confundir elección de maquinaria con semántica. Examinar acceso, construcción/conversión, comparación, codecs, alias de host, Unicode escalar, Native Image y consecuencias de interop; cualquier cambio duradero de arquitectura de Strings necesita justificar su frontera y no alterar semántica.

**Map:** almacenamiento estructural con `Entry[]`, índices y hash registradas, no una lista absurda de octetos: el protocolo `==/hash` de claves puede ser redefinido y enviar mensajes. Un `HashMap<Object,Object>` host no implementa las mismas reglas. **KEEP** su representación por evidencia semántica; revisar reentrada de callbacks, mutabilidad, snapshots, orden y colisiones.

**IdentityMap:** genera snapshots con generaciones que se separan al escribir y tablas de identidad Protos, no de referencia host indiscriminada. Por especificación, Number y String tienen identidad por valor aunque el wrapper Java cambie; no basar IdentityMap directamente en `IdentityHashMap` de los objetos Protos para las claves valor. **KEEP** generación y semántica; reforzar pruebas con Long fuera de caché, Strings rematerializados, NaN y nuevos BigInteger iguales.

**Números:** `Long`/`Double` primitivos y `ProtosLargeIntegerValue` siguen exactamente la separación PLAT056 de tipo semántico y tipo físico. `ProtosNumericValueSupport.isCurrentFloat` reconoce tanto `Double` como `ProtosFloatValue`: cualquier política de almacenaje `double[]` que exija únicamente `instanceof Double` para un Float huésped genuino dejaría un caso semánticamente elegible sin cobertura. Auditar también esa transición; el Array existente especializa por clase host `Double` y la Matrix R2 reconoce genuinos `Float`. Esto es **asimetría de admisión al backing**, no violación semántica confirmada.

**Slots y closures:** `ProtosObjectValue` usa `DynamicObject/Shape` y `ProtosExecutionContextValue` establece una autoridad léxica única (durable/frame), no un `Map` paralelo obligatorio en rutas ordinarias; `ProtosLexicalCell` puede guardar cualquier objeto de Protos y no debe hacerse `long[]` sin demostrar una equivalencia de todo el dominio y la captura. Contrastar con `FrameDescriptor`/typed Truffle frame slots en la auditoría siguiente, pero **no deshacer** PLAT036 como parte de esta reconciliación.

**Environment / recursos:** `Environment` retiene entradas nativas con validez de nombres host diferente de String Unicode portable; archivos, procesos, TCP, Futures, referencias Actor y FFI son valores/capacidades con autoridad y ciclo de vida, no secuencias homogéneas. Las representaciones de handles y recursos no deben empacarse como un tipo numérico o Bytes para «homogeneidad». Los wrappers de anchura fija `ProtosFixedIntegerInteropValue` son proyecciones de la frontera host, no nuevos Integers estándar.

## 6. Hallazgo AUD024-F4 — revisión extremo a extremo de los octetos

| Ruta examinada | Hecho de fuente | Obligación de corrección en la reconciliación |
|---|---|---|
| `ProtosStandardEncodingProtocol` | `Encoding.encodeForRuntime` crea `byte[]` y un `ProtosBytesValue` rellenado vía `indexedAdd` por octeto; decode crea nuevo `byte[]` desde snapshot de objetos | Construcción de un Bytes fresco directamente desde contenido binario **validado/copied/owned**, sin convertir un bloque en lista de Objects; mantener tipo, BOM y errores |

| `ProtosActorValueTransfer` / `ProtosParallelRuntime` / `ProtosDetachedExecutionValue` | Copier de grafos y reconstrucción Bytes por `indexedSnapshot()` + octetos | Contenido puede copiarse en bloque **solo** junto con reconstrucción de identidad, delegación, slots, ciclos, aliases y semántica de errores |
| `std:sqlite/internal/Borrowed.protos` | `library.copy(region,count)` da vista sobre `byte[]`, seguida de `while` con `bytes.add(copied[position])` | Discontinuidad física evidente; no inventar API pública FFI. La solución del puente Protos-first se coordina con D261 pendiente |
| `std:sqlite/abi.protos` | `bindBlob` convierte Bytes en String Latin1 para transportarlo por admisión D188 | Adaptación privada de contrato vigente; no ratificar ni ampliar FFI con este AUD |
| `std:io/files/module.protos` | `readAllBytes` concatena octetos por mensajes `Bytes.add`; `writeAllBytes` hace snapshot con Latin1 y chunks por octeto | Mantener protocolos/fallos y snapshot sin hacer un nuevo selector público por decisión de audit; optimización de bulk huésped requiere protocolo acordado |
| `std:http/internal/MessageBody.protos` y rutas HTTP | Framing y validación de cabeceras/bodies por octeto, además de copias | No suprimir bucles semánticos (límites, aceptación, chunk delimiters); solo materialización intrínsecamente binaria donde la propiedad esté clara |

La parte de **objeto Bytes con byte[]** se puede corregir independientemente de aceptar nuevas operaciones de movimiento masivo entre proveedores. Una conversión que hoy es un bucle *de mensajes Protos observables* no puede declararse equivalente a una memcpy sin demostrar que la semántica exacta de envío, redefinición y selección lo permite. Si se requiere un nuevo selector público o admisión FFI, se registra **DESIGN GATE**, no se oculta en el cambio Java.

## 8. Escenarios de falsación y batería de conformance **antes de declarar corregido**

1. **Bytes `byte[]`**: 0, 1, 127, 128, 255; rechazo de -1/256/Float y de objeto Java no guest mediante acceso directo; prohibición de exposición host en `InteropLibrary`; copia/bloque independiente; `add/atPut` retornan el objeto exacto; `removeAt` correcto; `each` snapshot con mutación y no-local return; parent correcto; open/closed/frozen; lecturas async que reutilizan backend array.
2. **Array**: todas las generaciones `long[]`, `double[]`, `boolean[]`, `Object[]`; entrada `Long.MAX_VALUE/MIN_VALUE`, Float -0.0/NaN, cambio homogéneo→heterogéneo, snapshots COW antes y después de mutación, generacion COW y test de `Long` distinto de Integer host, zero-length, close/freeze y `each`.
3. **Vector**: todo SmallInteger, todo Float, mezcla, Fraction/Complex/BigInteger, y secuencia que se generaliza en `atPut`; cada retorno exactamente Number correcto; rechazo de Boolean, Object, String y foreign; snapshot `each` reentrante, cancelación/non-local, copy/scale/dot, identidad y transfer.
4. **Matrix**: 0×n y n×0 con dimensiones matemáticas grandes; row-major, overflow de volumen e índices; all-long, all-Float, mezclas; Float→general y long→general; `Matrix.matmul` con diferentes combinaciones y strict D214-F1, -0.0, NaN, Infinity y orden de reducción; `readonlyPackedFloatsForRuntime()` no debe asumir `Object[]` en presencia de `long[]`; frozen readers; retorno `atPut`, snapshot y Actor/P transfer.
5. **Numéricos**: SmallInteger/BigInteger en exactamente ±2^63, promoción sin truncamiento, Fraction/Complex exactos, Float signed zero y NaN en igualdad e `identityHashOf`, doble representación `Double` y `ProtosFloatValue`, no conversión implícita a double.
6. **Identidad**: dos Array/Bytes/Vector/Matrix con contenido igual siguen distintos por `===`; Number/String iguales con distintas representaciones host siguen `===`; todas las claves Map/IdentityMap respetan `hash`, `==`, `===` y colisiones y no reanudan tras un error.
7. **Transferencia**: grafo con fuente repetida y ciclos en slots, nested Bytes/Vector/Matrix, materialización en Actor destino y P, separación de mutaciones sin compartir buffer; origen frozen con memoria físicamente compartible solo si inobservable.
8. **String**: secuencias con caracteres BMP, suplementarios, combinantes, ZWJ, surrogate aislado inválido, concatenación y decodificación, longitud por escalar (no UTF-16 ni graphemes), comparación/hash por valor e interop host.
9. **I/O y FFI**: Size 0 permitido donde el contrato lo permita (pero `read(0)` se rechaza), chunks, EOF, error, cancelación, BOM, Latin1, borrowed memory tras invalidación, ausencia de retención de buffer nativo, bytes `00 80 FF`.
10. **Política de pruebas:** ejecutar solo por el humano, primero tests afectados de Java (`ProtosStandardBytesProtocolTest`, `ProtosAdditionalIndexedInteropTest`, `ProtosArrayValueTest`, tests específicos de Matrix/Vector) y suites de conformance de `protos/tests/conformance/bytes`, `protos/tests/library/math/linear-algebra`, encoding, I/O y transfer; finalmente conjunto integrado exigido por `AGENTS.work/IMPLEMENTATION.md`. Los tests existentes **no se han ejecutado ni se declara PASS**.

**Defecto de cobertura comprobado:** `bytesHostOnlyElementFailsClosed` documenta una representación internamente inválida en lugar de impedirla; si se cambia a `byte[]` la prueba debe esperar rechazo temprano del write Java. Los tests Java de Bytes existentes tienen varios `assertSame(Long, indexedAt)`; la identidad de Java Long cacheado es un accidente de representación, mientras que `===` de Integer por valor es la garantía. Mantener `assertSame` cuando la API de mensaje devuelve la **referencia exacta del argumento** (`add`, `atPut`), pero no imponer esa restricción en el valor **almacenado y reificado** por `at`, si la identidad semántica queda intacta.

## 9. Dictamen, separaciones de autoridad y propuesta de ejecución

**AUD024-R1 — RECONCILE Bytes:** objetivo técnico confirmado por el propietario: representar octetos reales mediante un `byte[]` dentro de `ProtosBytesValue`, impedir estados host inválidos desde el almacenamiento, y poner en concordancia constructores, snapshots, interop, codificación, I/O y transfer. **AUD024-R5 — frontera FFM/SQLite:** registrar como hallazgo la reconstrucción byte por byte tras la copia FFM. No aprobar aquí un nuevo método FFI o cambio de admisión; D261 es propietario y su API exacta aún no está ratificada. No volver a introducir ByteRegion (D161).
